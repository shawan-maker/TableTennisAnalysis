## 竞品调研设计原则（参考 13 个产品）

> 以下原则从前端设计 v2.0 和竞品调研报告中提炼，指导产品全阶段设计。

| 原则 | 来源教训 | 我们的做法 |
|---|---|---|
| 5 Tab 不膨胀 | Keep 从 2→5+子类目，用户不满 | 固定 5 Tab，子功能通过层级管理 |
| 免费足够好用 | Keep 大量免费转付费，白嫖用户流失 | 每日免费 AI 分析 3 次，基础功能永久免费 |
| 广告克制 | Keep/咕咚广告密集影响体验 | 仅信息流原生广告，无开屏/弹窗，会员去广告 |
| 社区真实 | Keep 社区水化、营销号泛滥 | 鼓励真实运动数据关联的内容，建立审核机制 |
| AI 功能扎实 | Keep AI 教练价值未验证出现 bug | AI 分析充分测试后上线，确保结果准确 |
| 创作者分成合理 | Keep 头部教练出走 | 创作者分成不低于 75-80%，提供独家保护 |
| 付费墙适度 | B站/抖音 7 天观看权过短 | 付费内容永久观看（或至少 90 天） |

### Phase 0 关键技术结论

**AI 视频分析**：
- 推荐使用 TTNet（CVPR 2020，专为乒乓球设计）和 TrackNetV5（2025）而非通用 YOLO
- 球体追踪推荐卡尔曼滤波 + 抛物线物理模型，**DeepSORT 不适用**（为行人设计，球体外观单一）
- 动作识别：2D 姿态 + Temporal CNN 达 99.37% 准确率
- 球速估算误差 20-30%（30fps + 单目限制），展示时用范围值
- 云 GPU：T4 实例 ~1.87 元/小时，月成本约 354 元
- 关键数据集：OpenTTGames（55,582 样本）、TTStroke-21（21 类动作）

**3D 数字人物教学**：
- 确定 Three.js + React Three Fiber（轻量 ~500KB，小程序有 threejs-miniprogram 适配）
- Unity WebGL **排除**（包体 >10MB）
- 角色模型：ReadyPlayerMe + Blender 后处理（免费，版权风险极低）
- 乒乓球专项动画无现成资源，需 Blender 关键帧动画自主制作
- 交互功能（旋转/慢放/逐帧/标注）全部有成熟 API 支持

## Phase 1：核心 MVP（4–6 个月）

> **目标**：上线完整的核心闭环（数据→视频分析→报告→训练建议→付费），综合验证产品价值
> **对应 Tab**：首页 + 训练 + 赛事（记分牌）+ 我的

### 模块 1：首页 / Dashboard

- **数据概览卡片**：本月战绩（胜率）、分析次数、训练频次
- **快捷操作宫格**：上传分析 / 开始记分 / 录入数据 / 数据看板
- **训练打卡日历**：月度训练打卡可视化，连续打卡火焰图标 🔥
- **最近分析报告列表**：快速进入报告详情
- **训练提醒**：展示上次分析报告的训练建议摘要

### 模块 2：用户系统

- 微信登录（小程序）/手机号登录（App）
- 个人档案：
  - 开球网积分（用户填写开球网用户名/ID 或直接填写积分）
  - 自评水平（未注册开球网用户的补充选项）
  - 打法类型（快攻/弧圈/削球/全面等）
  - 装备配置（底板+胶皮，可后续补充）
- 积分历史记录（用户定期更新，后续对接开球网 API 自动同步）
- **乒乓大数据**（参考开球网）：趣味统计卡片（战胜最高分、连胜纪录、比赛城市数、交手人数、间接战胜马龙/孙颖莎等）
- **账号注销**：用户可申请注销账号，72h 冷静期后永久删除个人信息（手机号/位置/头像），视频转为匿名归档（PIPL 被遗忘权）
- **数据导出**：用户可导出个人数据（JSON 格式：档案/比赛记录/分析报告摘要），满足 PIPL 数据可携带权

> **不建独立积分体系**——开球网是国内乒乓球的事实标准，系统延用。积分用于水平匹配、训练方案难度自适应、社区内容推荐。

### 模块 3：视频分析核心 ⭐

- 视频上传（手机拍摄引导：侧后方斜 45° 高位角度建议、时长限制）
- AI 自动分析（异步处理，后台排队）：
  - 球体检测与轨迹追踪（基于 TTNet/TrackNet 架构）
  - 落点区域分布（九宫格热图）
  - 技术动作识别（正手/反手/发球等大类）
  - 回合统计（回合长度、击球频率、攻防转换）
  - 得分分析（如果可识别比分）
- 分析报告自动生成：
  - 数据可视化（落点热图、技术环形图、节奏折线图）
  - 文字分析结论（基于规则引擎 + 专业知识库）
  - 改进建议（关联训练方法）
  - 视频回放带关键帧标记（第N板 + 技术动作 + 得分/失分）
- 分析结果反馈机制（用户标记"对/不对"，数据回流用于模型优化 → 数据飞轮）

### 模块 4：手动数据与记分牌

- 智能记分牌（实时记分 + 得分方式标记 → 自动生成比赛数据）
  - 大按钮单手操作、得分方式快速标记（发球得分/相持得分/对手失误等）
  - 自动轮换发球、关键分标记、换边提示
- 比赛数据手动录入（快速录入模板，支持只录总比分不逐分记录）
- 数据看板（战绩趋势、技术统计、累计落点热图、比赛记录列表）

### 模块 5：训练建议（基于历史数据对比）

> **核心原则**：训练建议必须基于历史数据分析对比，不可仅基于单次分析报告。每次分析后自动生成进度快照，积累后形成技术指标趋势，使训练建议和方案更加科学。

- **进度快照自动生成**：每次 AI 分析完成后，自动从分析结果中提取 18 项关键指标生成进度快照，永久保留
- **技术指标趋势分析**：基于历史快照计算每项指标的变化方向（改善/停滞/退步）、变化率和持续性
- **基于历史对比的训练建议**（非单次快照式）：
  - 进步确认："你的反手使用率从 18% 提升到 25%，进步明显"
  - 持续问题警告："正手落点集中问题已持续 3 次分析未改善，建议调整训练方法"
  - 新问题识别："本次分析发现反手拉球引拍过大，历史报告中未出现过"
  - 已改善确认："发球落点单一问题已改善（最近 2 次分析不再出现）"
- **报告对比功能**：用户可选择任意两次历史分析报告进行对比（技术统计/落点/回合/球速/问题变化）
- 训练计划模板（按问题类型 + 趋势状态推荐训练方案框架，Phase 2 提供可执行训练单生成）

> 学习视频库不在 Phase 1，教学内容库移至 Phase 3 社区模块。
> 进度分析模块（progress_analysis）在架构设计中详细设计，见架构文档第 12.7 节。

### 模块 6：游戏化设计（参考 HomeCourt/咕咚）

- **训练积分**：完成训练/分析/记分获得积分
- **训练打卡日历**：月度打卡可视化，连续打卡激励
- **首组徽章**：首次分析、首胜、连续训练 7 天等基础徽章

### 模块 7：付费闭环

- 免费版：每日 3 次分析 + 手动数据 + 记分牌 + 基础看板 + 社区浏览（Phase 3 上线）
- 付费版：无限视频分析 + 训练方案模板 + 历史对比
- 微信支付集成

### 支撑模块：通知服务

- 消息推送（WebSocket 实时 + 离线推送）
- 涵盖：视频分析完成、比赛结束、训练建议更新、会员到期、系统公告
- 独立模块设计（切片 12-notification），不属于任何业务模块的附属功能

### 支撑模块：进度分析

- 技术指标趋势分析（基于历史快照计算改善/停滞/退步）
- 分析报告对比（任意两次报告的技术统计/落点/球速变化对比）
- 独立模块设计（切片 08-progress_analysis），见架构文档第 12.7 节

## Phase 2：智能教练升级（4–6 个月）

> **目标**：从"数据分析"升级为"AI 教练"，训练方案体系化
> **对应 Tab**：训练（扩展）+ 我的（徽章/报告）

### 模块 1：高级视频分析

- 球速估算（基于帧间位移 + 镜头标定，展示为范围值）
- 击球动作细节分析（引拍幅度、挥拍轨迹、击球点）
- 弧度分析（球飞行弧线参数提取）
- 对手分析（对手落点偏好、发球类型统计）

### 模块 2：3D 数字人物教学 ⭐

- 3D 数字人物动作模型库：
  - Three.js + React Three Fiber 创建可交互的 AI 数字人物
  - 角色模型完全原创，不使用任何真人形象或动捕数据
  - Blender 关键帧动画制作核心技术动作
  - 覆盖：正手拉球/攻球、反手拉/拨、搓球、发球、步法等
- 交互能力：360°旋转、4 档速度（0.25x/0.5x/1x/2x）、逐帧、关键部位高亮标注
- 关键姿势跳转（引拍/触球/随挥/还原）
- 动作切换 crossFade 过渡
- 用户视频 vs 3D 标准动作的对比分析（并排/叠加展示）
- 动作关键点标注（关节角度、拍面角度、重心位置）

### 模块 3：体系化训练方案（含动态调整闭环）

- 自动诊断核心短板（基于分析数据 + 历史趋势 + 专业知识库规则）
- 生成个性化训练计划（目标→训练内容→训练量→检验标准→周期）
- **进度追踪与方案动态调整**：
  - 每次新分析后，自动评估当前训练方案有效性（目标达成度）
  - 改善中 → 维持当前方案，确认进步
  - 停滞（连续 3 次无改善）→ 自动调整方案（更换训练方法/增加训练量）
  - 退步 → 诊断原因，调整方案重点
  - 已达标 → 设定新目标
  - 每次调整记录版本化保存（旧方案→新方案 diff + 调整原因）
- 训练单生成（每次训练的具体内容清单，可跟随执行）
- 训练单跟练模式

### 模块 4：深度数据分析

- 对手建模（习惯落点、发球偏好、弱点区域 → 一页 scout report）
- 训练负荷分析（训练量与水平变化关联）
- 趋势预测（基于历史数据预测水平变化趋势）
- 跨比赛对比分析

### 模块 5：月度训练报告

- 月度训练概览（训练次数、分析次数、比赛场次）
- 技术进步趋势（关键指标变化折线图）
- 训练负荷分析摘要（引用模块 4 训练量与水平变化关联结论）
- 本月成就展示
- 下月训练建议

### 模块 6：游戏化扩展

- **徽章/成就系统**（完整版）：进步徽章、百场徽章、分析达人等
- **训练打卡日历升级**：连续 30 天/100 天成就

## Phase 3：社区与社交（3–4 个月）

> **目标**：建立用户粘性和社交生态
> **对应 Tab**：社区（上线）+ 赛事（约球+球馆搜索扩展）+ 首页（推荐内容）

### 模块 1：社区交流

- 社区首页信息流（推荐/关注切换，穿插帖子/视频/问答三种内容）
- 帖子/动态详情（内容/评论/点赞/收藏/分享）
- 发布动态（图文/视频/分析报告分享/技术问答，标签选择）
- 技术问答（提问/回答/最佳答案）
- **圈子/话题**：技术交流/装备测评/约球交友/赛事讨论/青少年乒乓/教练交流/球馆经营
- **排行榜**：周榜/月榜/总榜（训练达人/分析达人/社区内容榜）

> 参考 Keep 社区+B站信息流。避免 Keep 社区水化问题：鼓励真实运动数据关联的打卡。

### 模块 2：学习视频平台（混合模式）

- **嵌入模式**：聚合公开教学视频，引用原平台播放器嵌入（不下载不重新托管，无版权风险）
- **授权本地化**：与优质创作者达成授权，本地化存储（创作者授权+收益分成），支持慢放/逐帧/离线
- **UGC 上传**：用户/教练上传原创教学视频，创作者自主定价（免费或付费），平台抽成
- 视频分类（技术类型/难度）、搜索、推荐
- **跟练模式**（仅授权本地化和 UGC 支持）：慢放/循环/逐帧、技术要点文字同步高亮、投屏
- 与 AI 分析联动：基于用户分析报告智能推荐相关教学视频
- 创作者激励：优质内容获得流量倾斜

### 模块 3：创作者中心（参考 B站/抖音）

- 创作者上传流程：上传→填写信息→定价（免费/付费）→审核→上线
- 创作者数据概览：总播放量、粉丝数、月度收益
- 作品管理：编辑/数据/收益
- 收益记录和提现
- **创作者分成不低于 75-80%**，平台抽 20-25%

### 模块 4：同城约球（参考咕咚）

- 约球列表（附近球友，基于 LBS 定位）
- 约球详情（时间/地点/水平要求/已报名/留言）
- 发布约球（时间/地点/水平要求/人数/费用/备注）
- 约球管理（我的发布/我的报名）
- 水平匹配（基于开球网积分匹配实力相近球友）

### 模块 5：球馆搜索（参考大众点评）

- 地图模式 + 列表模式双视图
- 球馆搜索（距离/价格/设施筛选）
- 球馆详情（设施信息/价格/用户评价/近期赛事/导航）
- 用户评价系统

### 模块 6：教练入驻

- 教练列表（资历/评分/服务项目/价格，筛选）
- 教练详情（简介/服务项目/学员评价/预约）
- 线上指导服务（视频分析指导/月度训练指导，教练定价平台抽成）

## 技术方向（基于 Phase 0 验证结果更新）

### 跨平台方案

> 跨平台框架：Taro 4（React 体系），架构设计最终确定，排除 uni-app。

### 后端架构方向

- **云原生 + Serverless**：最大化减少运维
- **统一 FastAPI 后端**（架构设计最终确定，放弃微信云开发双后端方案）
- **AI 推理**：云端 GPU 按需调用（阿里云/腾讯云 T4 实例，~1.87 元/小时）
- **视频处理流水线**：上传 → 存储 → AI 分析 → 报告 → CDN 分发
- **数据库**：PostgreSQL + PostGIS（架构设计最终确定，排除 MongoDB）
- **缓存与会话**：Redis 7+（Token 管理、限流计数、实时比分、健康检查标记）
- **异步任务队列**：Celery + Redis Broker（AI 分析流水线、定时调度、72h 账户删除、日志清理）
- **实时通信**：WebSocket（FastAPI 内置，记分牌实时推送、分析进度通知）
- **对象存储**：阿里云 OSS / 腾讯云 COS

### AI 技术栈（Phase 0 确认更新）

| 能力 | 技术方案 | Phase 0 结论 |
|---|---|---|
| 球体检测 | **TTNet / TrackNetV5**（乒乓球专用，非通用 YOLO） | TTNet（CVPR 2020）开源成熟，TrackNetV5（2025）最新 |
| 球体追踪 | **卡尔曼滤波 + 抛物线物理模型**（非 DeepSORT） | DeepSORT 为行人设计，球体外观单一不适用 |
| 球台检测 | YOLO + 关键点检测（球台四角定位） | 方案标准化 |
| 落点估算 | 轨迹预测 + 球台平面单应性矩阵映射 | 依赖球检测级联精度 |
| 人体姿态 | MediaPipe / MMPose | MediaPipe 轻量适合移动端 |
| 动作识别 | 2D 姿态 + Temporal CNN | **99.37% 准确率**（有论文验证） |
| 球速估算 | 帧间位移 + 帧率 + 镜头标定 | **误差 20-30%**，展示用范围值 |
| 报告生成 | 规则引擎 + LLM | — |

### 3D 数字人物教学技术（Phase 0 确认更新）

| 能力 | 技术方案 | Phase 0 结论 |
|---|---|---|
| 3D 渲染引擎 | **Three.js + React Three Fiber** | 轻量 ~500KB，小程序有 threejs-miniprogram 适配 |
| ~~Unity WebGL~~ | ~~排除~~ | 包体 >10MB，不适合移动端 |
| 数字人物模型 | **ReadyPlayerMe + Blender 后处理** | 免费生成 GLB，版权风险极低 |
| 动作动画 | **Blender 关键帧动画** | 乒乓球专项无现成资源，需自主制作 |
| 交互层 | OrbitControls + AnimationMixer | 旋转/慢放/逐帧/标注全部可实现 |
| 模型压缩 | Draco 压缩 ≤2MB | 确保首屏加载 ≤3 秒 |

## 数据飞轮设计

```
用户上传视频 → AI 分析 → 用户反馈（对/错标记）→ 标注数据积累 → 模型 fine-tune → 分析精度提升 → 更好体验 → 更多用户上传
```

这是产品的核心壁垒：先发者积累的数据越多，后来者越难追赶。
