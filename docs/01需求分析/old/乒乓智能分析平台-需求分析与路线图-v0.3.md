# 乒乓智能分析平台 — 需求分析与路线图 v0.3

> **版本**：v0.3
> **日期**：2026-10-09
> **变更说明**：基于用户反馈更新——取消独立积分体系（延用开球网）、专业知识改为在线搜集、3D教学改为 AI 数字人物、学习视频移至 Phase 3 社区模块（UGC+创作者经济模式）

---

## 已确认的关键决策

| 决策项 | 确认结果 | 对架构的影响 |
|---|---|---|
| 目标市场 | 中国市场为主 | 微信生态优先，开球网/高德地图/微信支付 |
| 视频分析 | 全自动（用户无感） | 流程全自动，精度分阶段提升；需 AI 云服务支撑 |
| 专业资源 | **在线搜集汇总**（张指导乒乓等内容创作者的公开教学） | 不依赖线下访谈，知识库通过整理公开内容建设 |
| 积分体系 | **不建独立积分，延用开球网** | 用户填写开球网积分/ID，后续对接 API 自动同步 |
| 3D教学 | **AI 数字人物建模**，不用真人 | 规避肖像权/版权风险，3D引擎驱动可交互教学 |
| 学习视频 | **Phase 3 社区模块，UGC + 创作者经济** | 初期聚合公开内容免费引流，后期创作者自主定价+平台抽成 |
| 团队 | 个人开发+AI辅助 | 架构极简化，最大化云服务，最小化运维 |
| 平台 | 小程序+App同步 | 跨平台框架统一开发 |
| MVP验证 | 综合验证 | Phase 1 覆盖数据+视频+付费完整闭环 |

## 修订后的分阶段路线图

### Phase 0：技术预研与知识储备（1–2 个月）

> **目标**：验证核心技术可行性，建立专业知识库

**并行任务**：

**A. 专业知识建设（在线搜集模式）**
- 从公开教学内容（张指导乒乓等专业创作者的视频/文章）中系统搜集：
  - 技术动作体系（完整分类树 + 各动作标准要点）
  - 常见技术问题与训练方法（问题→诊断→纠正→训练手段）
  - 数据分析维度定义（哪些指标重要、优先级排序）
  - 训练方案结构模板
- 将零散内容**提炼转化为结构化知识库**（不是搬运视频，而是提取专业知识和方法论）
- 产出：专业知识库 v1（结构化文档 + 可机读的数据结构）

> **版权说明**：提取的是乒乓球技术和训练方法论（属于公有领域的事实知识），不是直接搬运内容创作者的视频或文字。知识库以自有的结构化表述组织。

**B. AI 视频分析技术验证**⭐最关键
- 乒乓球检测与追踪原型（用 YOLO/DeepSORT 等，验证能否从视频中检测到球）
- 球台检测与参考系建立（从画面中识别球台，建立坐标映射）
- 落点估算原型（基于球轨迹 + 球台平面，估算落点区域）
- 动作识别原型（用 MediaPipe 人体姿态估计 + 简单分类器，验证能否区分正手/反手）
- 产出：技术可行性验证报告 + 原型 Demo

**C. 3D 数字人物教学原型**
- 验证 3D 角色动画技术路线（Three.js / Unity WebGL）
- 获取/创建一个 rigged 3D 人物模型
- 制作 1–2 个核心技术动作的动画原型（如正手拉球）
- 验证：旋转视角、慢放、逐帧查看的交互体验
- 产出：3D 教学原型 Demo

**D. 技术架构设计**
- 跨平台框架选型（Taro vs uni-app vs Flutter+小程序）
- 云服务选型（AI 推理服务、对象存储、数据库、CDN）
- 系统架构设计（详见后续架构设计文档）

> **Phase 0 的核心判断点**：
> 1. 视频 AI 分析：球体检测成功率 >70%、落点估算准确率 >60% → 技术路线可行
> 2. 3D 教学：能否在 Web/移动端流畅渲染可交互的 3D 人物动作 → 技术路线可行

### Phase 1：核心 MVP（4–6 个月）

> **目标**：上线完整的核心闭环（数据→视频分析→报告→训练建议→付费），综合验证产品价值

**功能模块**：

#### 模块 1：用户系统
- 微信登录（小程序）/手机号登录（App）
- 个人档案：
  - 开球网积分（用户填写开球网用户名/ID 或直接填写积分）
  - 自评水平（未注册开球网用户的补充选项：初学/业余中级/业余高级/竞技级）
  - 打法类型（快攻/弧圈/削球/全面等）
  - 装备配置（底板+胶皮，可后续补充）
- 积分历史记录（用户定期更新，后续对接开球网 API 自动同步）

> **不建独立积分体系**——开球网是国内乒乓球的事实标准，用户信任它，系统延用即可。积分用于水平匹配、训练方案难度自适应、社区内容推荐。

#### 模块 2：视频分析核心⭐
- 视频上传（手机拍摄引导：角度建议、时长限制）
- AI 自动分析（异步处理，后台排队）
  - 球体检测与轨迹追踪
  - 落点区域分布（九宫格热图）
  - 技术动作识别（正手/反手/发球等大类）
  - 回合统计（回合长度、击球频率、攻防转换）
  - 得分分析（如果可识别比分）
- 分析报告自动生成
  - 数据可视化图表（落点热图、技术占比、节奏曲线）
  - 文字分析结论（基于规则引擎 + 专业知识库）
  - 改进建议（关联训练方法 + 教学内容推荐）
- 分析结果反馈机制（用户标记"这个分析对/不对"，数据回流用于模型优化）

#### 模块 3：手动数据与记分牌
- 智能记分牌（实时记分 + 得分方式标记 → 自动生成比赛数据）
- 比赛数据手动录入（快速录入模板）
- 数据看板（胜率曲线、技术占比、落点热图、趋势分析）

#### 模块 4：训练建议
- 基于分析报告的训练建议（文字建议，关联专业知识库中的训练方法）
- 训练计划模板（按问题类型推荐训练方案）

> **学习视频库不在 Phase 1**：教学内容库移至 Phase 3 社区模块。Phase 1 的训练建议以文字 + 数据图表为主，后续在 Phase 2 补充 3D 数字人物教学，Phase 3 补充 UGC 学习视频。

#### 模块 5：付费闭环
- 免费版：手动数据 + 记分牌 + 基础看板 + 社区浏览
- 付费版：视频分析（按次或包月）+ 训练方案
- 微信支付集成

**验证指标**：
| 指标 | 目标 |
|---|---|
| 注册用户 | 1000+ |
| 视频分析使用次数 | 500+ |
| 分析准确度用户满意度 | >70% |
| 付费转化率 | >5% |
| 次日留存率 | >30% |

### Phase 2：智能教练升级（4–6 个月）

> **目标**：从"数据分析"升级为"AI 教练"，训练方案体系化

**功能模块**：

#### 模块 1：高级视频分析
- 球速估算（基于帧间位移 + 镜头标定）
- 击球动作细节分析（引拍幅度、挥拍轨迹、击球点）
- 弧度分析（球飞行弧线参数提取）
- 对手分析（对手落点偏好、发球类型统计）

#### 模块 2：3D 数字人物教学⭐
- 3D 数字人物动作模型库：
  - 使用 3D 引擎（Three.js / Unity WebGL）创建可交互的 AI 数字人物
  - 角色模型为完全原创的 3D 数字人，**不使用任何真人形象或动捕数据**
  - 动作动画通过关键帧动画制作，或基于通用运动参数生成
  - 核心技术动作覆盖（正手拉球/攻球、反手拉/拨、搓球、发球、步法等）
- 交互能力：360°旋转视角、慢放、逐帧、关键部位高亮标注
- 用户视频 vs 3D 标准动作的对比分析（并排/叠加展示）
- 动作关键点标注（关节角度、拍面角度、重心位置）

> **版权安全**：3D 数字人物为完全原创角色，动作动画为自制/通用参数生成，不涉及任何真人肖像权、著作权或动捕数据版权问题。

#### 模块 3：体系化训练方案
- 自动诊断核心短板（基于分析数据 + 专业知识库规则）
- 生成个性化训练计划（目标→训练内容→训练量→检验标准→周期）
- 训练进度追踪（定期分析对比，方案动态调整）
- 训练单生成（每次训练的具体内容清单，可跟随执行）

#### 模块 4：深度数据分析
- 对手建模（习惯落点、发球偏好、弱点区域 → 一页 scout report）
- 训练负荷分析（训练量与水平变化关联）
- 趋势预测（基于历史数据预测水平变化趋势）
- 跨比赛对比分析

---

### Phase 3：社区与社交（3–4 个月）

> **目标**：建立用户粘性和社交生态

**功能模块**：
- 社区交流（动态/帖子、分析报告分享、技术问答）
- 同城约球（LBS 定位、约球发布、水平匹配、球馆推荐）
- 教练入驻（线上指导、答疑、学员管理）
- **学习视频平台（混合模式）**：
  - **嵌入模式**：聚合公开教学视频，引用原平台播放器嵌入播放（不下载不重新托管，无版权风险，零存储成本），快速建立内容覆盖度
  - **授权本地化**：与优质内容创作者达成授权协议，获取可本地化存储的视频（创作者授权 + 收益分成），统一播放器体验（慢放/逐帧/离线）
  - **UGC 上传**：用户/教练上传原创教学视频，创作者自主定价（免费或付费），平台抽成
  - 按技术类型/难度分类，支持跟练模式（慢放/循环/逐帧）
  - 与 AI 分析联动：基于用户分析报告智能推荐相关教学视频
  - 创作者激励：优质内容获得流量倾斜

> **学习视频商业模式**：平台作为内容发现和交易撮合平台。三种内容来源分层：
> 1. 嵌入模式（公开内容引流，免费）→ 2. 授权本地化（提升体验，创作者分成）→ 3. UGC 上传（创作者经济，平台抽成 10–20%）
>
> **版权策略**：不直接下载他人视频。本地化存储仅限于有授权的创作者内容和用户原创上传。嵌入模式引用原平台播放器，不承担内容存储和版权责任。
>
> **与 3D 教学的关系**：3D 数字人物教学（Phase 2）= 平台自有核心教学资产（付费会员权益）；学习视频（Phase 3）= 社区内容（嵌入+授权+UGC混合）。两者互补：3D 模型教标准动作，创作者视频教实战经验和技巧。

## 修订后的技术方向概要

> 详细的架构设计将在下一阶段输出，此处先确定方向。

### 跨平台方案对比

| 方案 | 优势 | 劣势 | 适配度 |
|---|---|---|---|
| **Taro 4（React 语法）** | 一套代码 → 小程序+H5+App(RN)，React 生态，社区活跃 | App 端 RN 体验不如原生，复杂动画性能一般 | ★★★★☆ |
| **uni-app（Vue 语法）** | 一套代码 → 小程序+H5+App，Vue 生态，DCloud 云打包 | App 端体验中等，深度定制受限 | ★★★★☆ |
| **Flutter + 小程序双栈** | Flutter App 体验最好，小程序原生开发 | 两套代码维护，工作量大 | ★★★☆☆ |
| **Flutter + Taro 组合** | App 体验最佳 + 小程序一套代码 | 两种技术栈，学习成本高 | ★★★☆☆ |

> **倾向建议**：Taro 4 或 uni-app（个人开发+AI辅助场景，一套代码极重要）。后续架构设计中详细对比后确定。

### 后端架构方向

- **云原生 + Serverless**：最大化减少运维，适合个人开发
- **微信云开发**（小程序端）+ **独立云服务**（App端 + AI 推理）
- **AI 推理**：云端 GPU 按需调用（阿里云/腾讯云 ECS GPU 或 Serverless GPU）
- **视频处理**：云端流水线（上传 → 存储 → AI 分析 → 报告 → CDN 分发）
- **数据库**：云托管数据库（MongoDB / PostgreSQL）
- **对象存储**：阿里云 OSS / 腾讯云 COS（视频和图片存储）

### AI 技术栈方向

| 能力 | 技术方案 |
|---|---|
| 球体检测 | YOLO 系列（YOLOv8/v11）fine-tune 乒乓球检测 |
| 球体追踪 | DeepSORT / ByteTrack（多目标追踪） |
| 球台检测 | YOLO + 关键点检测（球台四角定位） |
| 落点估算 | 轨迹预测 + 球台平面单应性矩阵映射 |
| 人体姿态 | MediaPipe / MMPose（人体关键点检测） |
| 动作识别 | 姿态时序序列 + LSTM/Transformer 分类 |
| 球速估算 | 帧间位移 + 帧率 + 镜头标定 |
| 报告生成 | 规则引擎 + LLM（大模型生成自然语言分析） |

### 3D 数字人物教学技术方向

| 能力 | 技术方案 |
|---|---|
| 3D 渲染引擎 | Three.js（Web端，轻量）/ Unity WebGL（功能完整）/ Unity（App端嵌入式） |
| 数字人物模型 | 原创 rigged 3D 角色（使用 Mixamo/ReadyPlayerMe 生成或自建） |
| 动作动画 | 关键帧动画（核心动作精确制作）/ 通用运动参数驱动（后续 AI 辅助生成） |
| 交互层 | 360°旋转、慢放、逐帧、关键部位高亮、关节角度标注 |
| 对比展示 | 用户视频画面 + 3D 标准动作并排/叠加渲染 |
| 分发形式 | WebGL 实时渲染（Web/小程序）/ 嵌入式 3D View（App） |

> **数据飞轮设计**：用户上传视频 → AI 分析 → 用户反馈（对/错标记）→ 标注数据积累 → 模型 fine-tune → 分析精度提升 → 更好体验 → 更多用户上传。这是产品的核心壁垒。

## 下一步计划

| 序号 | 任务 | 说明 | 优先级 |
|---|---|---|---|
| 1 | 在线搜集专业知识，整理知识库 v1 | 用户执行，从公开教学内容中提取结构化知识 | 最高 |
