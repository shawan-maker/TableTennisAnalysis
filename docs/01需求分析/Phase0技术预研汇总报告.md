### 任务 2：AI 视频分析验证方案

**整体可行性判断：✅ 可行（有条件）**

**各模块可行性**：

| 模块 | 可行性 | 关键发现 |
|---|---|---|
| 球体检测 | ✅ 可行 | TTNet（CVPR 2020）专为乒乓球设计，热力图检测；TrackNetV5（2025）最新；BlurBall（2025）解决运动模糊 |
| 球体追踪 | ✅ 可行 | 推荐卡尔曼滤波 + 抛物线物理模型，而非 DeepSORT（后者为行人设计） |
| 球台检测 | ✅ 可行 | YOLO-pose 关键点检测 + OpenCV 单应性矩阵，方案标准化 |
| 动作识别 | ✅ 可行 | 2D 姿态 + Temporal CNN 达 99.37% 准确率（有论文验证） |
| 球速估算 | ⚠️ 有条件 | 30fps + 单目限制，误差可能 20-30% |
| 落点估算 | ⚠️ 有条件 | 依赖球检测和坐标映射的级联精度 |
| 云 GPU 推理 | ✅ 可行 | T4 实例 ~1.87 元/小时，月成本约 354 元 |

**关键开源项目和数据集**：
- TTNet：PyTorch 实现，球检测+事件检测+语义分割
- TrackNetV1-V5：体育球体追踪最成熟算法族
- OpenTTGames 数据集：55,582 样本，120fps
- TTStroke-21 数据集：21 类动作，~50K 帧
- RacketVision（AAAI 2026）：最新大规模基准

**最大风险**：30fps 手机拍摄场景下球体检测的泛化能力

**验证计划**：5 步验证，6 周周期
1. 球体检测验证（2周）— 瓶颈模块，优先启动
2. 球台检测 + 坐标映射（1周）— 可与步骤1并行
3. 落点估算（1周）
4. 动作识别（1周）
5. 球速估算 + 集成测试（1周）

### 任务 3：3D 数字人物教学验证方案

**整体可行性判断：✅ 完全可行**

**技术选型结论**：

| 模块 | 选型 | 理由 |
|---|---|---|
| 3D 引擎 | **Three.js + React Three Fiber** | 轻量（~500KB）、生态最大、小程序有 threejs-miniprogram 适配、MIT 开源 |
| 角色模型 | **ReadyPlayerMe + Blender 后处理** | 免费生成 GLB 角色、自带 200+ 动画库、版权风险极低 |
| 动画制作 | **Blender 关键帧动画** | 乒乓球专项动画无现成资源，需自主制作（6 个关键姿势/动作） |
| AI 动作生成 | 暂不依赖 | 技术尚不成熟，作为未来储备 |
| 交互层 | OrbitControls + AnimationMixer | 360°旋转、慢放、逐帧、关节标注全部可实现 |

**关键发现**：
- 乒乓球专项动作动画**无现成资源**，必须用 Blender 关键帧动画自主制作
- 微信小程序通过 threejs-miniprogram 支持 WebGL
- 移动端优化后可达 30-60fps
- Unity WebGL 因包体过大（>10MB）被排除

**验证计划**：14 天 5 阶段
1. 环境搭建 + 模型获取（2天）
2. 角色加载 + 基础渲染（2天）
3. 动画制作 + 播放（4天）— 最耗时
4. 交互功能开发（3天）
5. 多端验证 + 性能优化（3天）

**成功标准**：桌面端 ≥60fps、移动端 ≥30fps、模型 ≤2MB、首屏 ≤3 秒

### 进入架构设计的条件

✅ **条件已满足**——三个任务的研究结果均表明技术路线可行，可以进入系统架构设计阶段。

### 架构设计需要考虑的关键约束

1. **AI 视频分析**：
   - 后端需要 GPU 推理服务（T4 实例，按需调用）
   - 视频处理异步流水线（上传→队列→分析→报告）
   - 球速估算精度有限（20-30%误差），架构上应支持多帧平滑和后续模型优化
   - 数据飞轮：用户反馈→标注数据→模型 fine-tune

2. **3D 教学**：
   - 前端使用 Three.js + React Three Fiber
   - 小程序端使用 threejs-miniprogram 适配
   - 3D 模型文件需 Draco 压缩（≤2MB）
   - Blender 动画制作需要纳入内容生产流程

3. **知识库**：
   - 结构化知识库需要设计为可机读的数据结构（非纯文档）
   - 规则引擎需要能够查询知识库生成训练建议
   - 训练方案模板需要参数化设计
