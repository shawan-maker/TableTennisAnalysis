> **版本**：v2.0（全阶段完整设计）
> **日期**：2026-10-09
> **变更说明**：基于竞品调研（13 个产品）重新设计信息架构，覆盖 Phase 1–5 全部页面
> **设计原则**：先做完整产品设计，再分阶段实施
> **参考来源**：开球网（赛事/积分）、HomeCourt（AI分析展示）、Keep（社区/会员）、咕咚（约球/赛事）、B站/抖音（创作者经济）、大众点评（场馆搜索）

## 一、设计系统

### 1.1 设计原则

| 原则 | 说明 | 竞品教训 |
|---|---|---|
| **运动专注** | 界面体现运动感和专业感 | 避免像 Keep 后期过度商业化稀释核心 |
| **数据驱动** | 数据可视化是核心体验 | 参考 HomeCourt 的热力图+数据卡片 |
| **操作极简** | 高频操作最少步骤完成 | 避免像 Keep 界面冗余功能堆砌 |
| **5 Tab 不变** | 底部导航 5 个 Tab 固定，子功能通过层级管理 | 避免 Keep 从 2→5+ 子类目膨胀 |
| **免费足够好用** | 基础功能永久免费，不过度收缩 | 避免 Keep 大量免费转付费导致流失 |
| **广告克制** | 仅信息流原生广告，无开屏/弹窗 | 避免 Keep/咕咚广告密集影响体验 |
| **社区真实** | 鼓励真实运动数据关联的内容 | 避免 Keep 社区水化、营销号泛滥 |

字体族：`-apple-system, "PingFang SC", "Helvetica Neue", "Microsoft YaHei", sans-serif`

### 1.4 间距与组件

- 8px 网格系统：4/8/12/16/24/32/48px
- 页面边距 16px，卡片内边距 16px
- 卡片：白底圆角 12px，阴影 `0 2px 8px rgba(0,0,0,0.06)`
- 按钮：主按钮（红底白字）、次按钮（白底红字红边）
- 标签：胶囊标签，分类型着色
- 空状态：插图 + 引导文字 + CTA
- 加载状态：骨架屏优先
- 底部弹窗：ActionSheet 用于选择和确认

### 1.5 游戏化设计元素（参考 HomeCourt/咕咚）

| 元素 | 说明 | 启动阶段 |
|---|---|---|
| 训练积分 | 完成训练/分析/记分获得积分 | Phase 1 |
| 徽章/成就 | 首次分析、连续训练7天、胜率超60%等 | Phase 2 |
| 训练打卡日历 | 月度训练打卡可视化 | Phase 1 |
| 排行榜 | 周榜/月榜（分析次数、训练频率、胜率） | Phase 3 |
| 实体奖牌 | 赛事完赛奖牌（可选购） | Phase 4 |

## 四、Tab 2：训练

### T2.1 视频分析 — 拍摄引导（Phase 1）⭐

> 详见 v1.0 文档 P1.3，核心不变。Phase 0 发现：最佳角度为侧后方斜 45° 高位。

**新增（Phase 5）**：多角度拍摄引导——支持双机位/三机位拍摄指引，用于专业级 3D 轨迹重建。

### T2.2 视频分析 — 处理中（Phase 1）

> 详见 v1.0 文档 P1.4。异步处理，步骤式进度（上传→转码→球体检测→动作识别→落点分析→报告生成）。

### T2.3 分析报告页（Phase 1）⭐⭐

> 详见 v1.0 文档 P1.5。核心页面：落点九宫格热图 + 技术环形图 + 节奏折线图 + 分析结论 + 视频回放带关键帧标记 + 反馈机制。

**Phase 2 扩展**：增加球速柱状图、落点散点图、攻防转换时间轴。球速展示为范围值（误差 20-30%）。

> 详见 v1.0 文档 P1.9。战绩趋势 + 技术统计 + 累计落点热图 + 比赛记录列表。

## 九、核心用户流程（全阶段）

### 流程 1：视频分析全流程（Phase 1）

```
首页 → [上传分析] → 拍摄引导 → 拍摄/选择 → 上传 → AI分析 → 报告 → 训练建议
                                                              ↓ [P2]
                                                         3D教学 → 对比分析
```

### 流程 2：记分牌全流程（Phase 1）

```
赛事Tab → [开始记分] → 设置 → 实时记分 → 结束 → 统计 → 数据看板 → 关联视频
```

### 流程 3：训练改进闭环（Phase 2）

```
视频分析 → 报告 → 诊断 → 训练方案 → 训练单 → 跟练 → 
  ↓                                          ↓
  └─── 下次分析 → 对比进步 → 方案调整 ←─────┘
```

### 流程 4：赛事报名全流程（Phase 4）

```
赛事Tab → 赛事列表 → 赛事详情 → 报名 → 缴费 → 
  ↓                                        ↓
  赛前提醒 → 参赛 → 成绩录入 → 积分更新 → 信用分
```

### 流程 5：约球全流程（Phase 3）

```
赛事Tab → 约球 → 附近列表 → 详情 → 报名 → 
  ↓                                    ↓
  约球提醒 → 到场 → 打球 → 记分 → 评价
```

### 流程 6：创作者变现流程（Phase 3）

```
社区Tab → 创作者中心 → 上传视频 → 定价 → 审核 → 
  ↓                                      ↓
  上线 → 用户观看 → 付费 → 平台抽成 → 创作者收益 → 提现
```

### 流程 7：新用户引导流程（Phase 1）

```
登录 → 填写档案（积分/打法） → 首页引导 → 
  [引导1] 录入比赛数据 → 看板 →
  [引导2] 上传视频分析 → 报告 → 训练建议
```

## 十、技术约束（Phase 0 结论）

| 约束 | 来源 | 对界面的影响 |
|---|---|---|
| AI 分析异步处理 | AI 验证方案 | 需队列/进度页面，非实时返回 |
| 球速误差 20-30% | AI 验证方案 | 球速展示为范围值，标注"估算" |
| 拍摄角度影响精度 | 专业知识库 | 需拍摄引导页，展示 45° 侧后方高位 |
| 落点九宫格分区 | 专业知识库 | 热图使用 3×3 九宫格 |
| 18 个数据维度 | 专业知识库 | 分析报告按重要性排序展示 |
| 10 个常见问题 | 专业知识库 | 训练建议关联问题-训练方法 |
| Three.js 3D 渲染 | 3D 验证方案 | 3D 查看器使用 WebGL |
| 模型 ≤2MB Draco | 3D 验证方案 | 首屏需骨架屏/加载动画 |
| 小程序 WebGL | 3D 验证方案 | 小程序用 threejs-miniprogram，可能降级 |
| 小程序视频限制 | 跨平台约束 | 小程序视频上传受限，引导到 App |
| 跨平台 Taro 4 | 架构方向 | 一套代码，小程序+App 界面一致（已确定使用 Taro 4，不使用 uni-app） |
| 开球网积分延用 | 用户决策 | 不自建积分，用户填写/API同步 |

### 小程序降级策略

| 功能 | App 体验 | 小程序降级 |
|---|---|---|
| 3D 教学查看器 | WebGL 完整渲染 | threejs-miniprogram 或跳转 H5 |
| 视频上传 | 系统相机/相册 | 受限 10MB，引导到 App |
| 视频分析 | 完整异步处理 | 同上 |
| 地图导航 | 原生地图 SDK | 微信地图组件 |
