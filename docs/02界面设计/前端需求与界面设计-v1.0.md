# 乒乓智能分析平台 — 前端需求与界面设计文档

> **版本**：v1.0
> **日期**：2026-10-09
> **适用范围**：Phase 1–4 全阶段前端页面需求与界面设计
> **技术基础**：基于 Phase 0 技术调研结果（AI 验证方案、3D 验证方案、专业知识库）

## 一、设计系统

### 1.1 设计原则

| 原则 | 说明 |
|---|---|
| **运动专注** | 界面风格体现运动感、专业感，不是泛泛的社交 App |
| **数据驱动** | 数据可视化是核心体验，图表要清晰、专业、可交互 |
| **操作极简** | 记分牌、数据录入等高频操作要最少步骤完成 |
| **渐进展示** | 首页只展示核心信息，详细数据在二级页面展开 |
| **跨端一致** | 小程序和 App 视觉统一，交互模式一致 |

### 1.2 色彩系统

```
主色（Primary）：#E63946（乒乓红 — 活力、运动、激情）
辅助色（Secondary）：#1D3557（深蓝 — 专业、信任、数据）
强调色（Accent）：#F4A261（橙黄 — 高亮、关键数据、CTA）
成功色：#2A9D8F（绿 — 得分、进步、完成）
警告色：#E76F51（红橙 — 失分、问题、风险）
背景色：#F1FAEE（浅灰白 — 主背景）
卡片色：#FFFFFF（白 — 卡片背景）
文字主色：#1D3557
文字次色：#6C757D
分割线：#DEE2E6
```

### 1.3 字体与排版

| 用途 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 大标题（页面标题） | 24px | Bold | 32px |
| 标题（卡片标题） | 18px | SemiBold | 26px |
| 正文（主要内容） | 15px | Regular | 22px |
| 辅助文字（说明、时间） | 13px | Regular | 18px |
| 数据数字（大数字展示） | 32px | Bold | 40px |
| 标签（标签、徽章） | 12px | Medium | 16px |

字体族：`-apple-system, "PingFang SC", "Helvetica Neue", "Microsoft YaHei", sans-serif`

### 1.4 间距系统

8px 网格系统：
- 间距档位：4px / 8px / 12px / 16px / 24px / 32px / 48px
- 页面边距：16px（小程序标准）
- 卡片内边距：16px
- 元素间距：8px / 12px
- 段落间距：16px / 24px

### 1.5 通用组件

| 组件 | 说明 |
|---|---|
| **卡片** | 白底圆角卡片（radius: 12px），阴影 `0 2px 8px rgba(0,0,0,0.06)` |
| **按钮** | 主按钮（红底白字）、次按钮（白底红字红边）、文字按钮 |
| **标签** | 圆角胶囊标签，分类型着色（技术类蓝色、问题类红色、优点类绿色） |
| **图表卡片** | 白底卡片内嵌图表，含标题 + 图表 + 说明文字 |
| **空状态** | 插图 + 引导文字 + CTA 按钮 |
| **加载状态** | 骨架屏（Skeleton）优先，避免空白等待 |
| **底部弹窗** | 从底部滑出的操作面板（ActionSheet），用于选择和确认 |

### 1.6 图标系统

使用线性图标风格，统一 2px 描边宽度。核心图标：
- 分析（图表）、记分（记分牌）、训练（哑铃/球拍）、社区（气泡）、我的（人像）
- 视频（播放）、上传（云上传）、位置（定位）、赛事（奖杯）、商城（购物袋）

### P1.3 视频分析 — 拍摄引导页 ⭐核心

**页面用途**：引导用户正确拍摄视频，提高 AI 分析准确率

> **Phase 0 发现**：知识库建议最佳拍摄角度为侧后方斜 45° 高位，该角度可同时观察到双方选手、球台全貌和落点区域。

**页面结构**：

```

│                                 │

│  │                         │   │
│  │   [拍摄角度示意图]        │   │
│  │   侧后方斜45°高位        │   │
│  │   ┌─────────┐           │   │
│  │   │ 📹 球台 │           │   │
│  │   │   全景  │           │   │
│  │   └─────────┘           │   │
│  │                         │   │
│  └─────────────────────────┘   │
│                                 │
│  📋 拍摄要求                     │
│  ✅ 角度：侧后方斜45°，高位拍摄   │
│  ✅ 距离：能看到整个球台          │
```

- "从相册选择"→ 系统相册选择视频文件
- 拍摄示意图用插画/3D渲染图展示正确角度
- 视频大小限制：500MB 以内，时长 3-10 分钟

## 七、技术约束（来自 Phase 0）

| 约束 | 来源 | 对界面的影响 |
|---|---|---|
| AI 分析异步处理 | AI 验证方案 | 需要队列/进度页面，不能实时返回结果 |
| 球速误差 20-30% | AI 验证方案 | 球速展示为范围值，标注"估算值" |
| 拍摄角度影响精度 | 专业知识库 | 需要拍摄引导页，展示正确角度 |
| 落点九宫格分区 | 专业知识库 | 热图使用 3×3 九宫格 |
| 18 个数据维度 | 专业知识库 | 分析报告按重要性排序展示 |
| 10 个常见问题 | 专业知识库 | 训练建议关联知识库中的问题-训练方法 |
| Three.js 3D 渲染 | 3D 验证方案 | 3D 教学查看器使用 WebGL |
| 模型 ≤2MB（Draco 压缩） | 3D 验证方案 | 首屏加载需骨架屏/加载动画 |
| 小程序 WebGL 支持 | 3D 验证方案 | 小程序端使用 threejs-miniprogram |
| 跨平台 Taro/uni-app | 架构方向 | 一套代码，小程序和 App 界面一致 |

## 八、响应式与适配

### 8.1 屏幕适配

- 设计基准：375px 宽度（iPhone 标准）
- 适配范围：320px–428px（小屏到大屏手机）
- 平板：双栏布局（Phase 3+ 考虑）

### 8.2 小程序特殊处理

- 小程序不支持部分 Web API（如 WebGL 部分、CSS 某些属性）
- 3D 教学模块在小程序中降级处理（或跳转 H5 页面）
- 视频上传受小程序限制（10MB 限制 → 需分段上传或引导到 App）

> **关键决策点**：小程序中的 3D 教学和视频上传可能需要降级处理或引导用户到 App。架构设计时需要考虑"小程序引导下载 App"的路径。
