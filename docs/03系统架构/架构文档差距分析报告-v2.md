## 二、v2.2 新发现的差距

### 2.1 需修复（P1 — 影响开发落地）

#### P1-1：ER 图 USER 实体定义重复

**位置**：§9.1 ER 图，约第 1496-1510 行

**现状**：Mermaid erDiagram 中 `USER` 实体定义出现了两次。第一次正常定义（含 `bigint id PK` 等字段），紧接着第 1504-1510 行重复了同样字段但没有实体名称头，导致 Mermaid 渲染异常。

**影响**：Mermaid 图渲染可能出错，开发人员对照 ER 图时产生困惑。

**建议**：删除重复的字段块（第 1504-1510 行），保留第一次定义。

---

#### P1-2：B 端工具 Phase 归属不一致

**现状**：

| 文档 | 位置 | Phase |
|------|------|-------|
| 需求 v0.4 | Phase 4 模块 8 | Phase 4（俱乐部管理/学员管理/批量分析） |
| 前端设计 v2.0 | 页面层级 | Phase 5（B 端 SaaS） |
| 架构 v2.2 | §15.3 扩展点表 | Phase 5（B 端 SaaS） |

**影响**：需求文档将 B 端工具放在 Phase 4，但前端设计和架构将其放在 Phase 5。如果按需求文档的节奏，Phase 4 需要额外设计 B 端功能，但架构和前端未覆盖。

**建议**：统一为 Phase 5。需求 v0.4 的 Phase 4 模块 8 移至 Phase 5 方向列表中。Phase 4 聚焦 C 端赛事/电商/信用分闭环。

### 2.2 应补充（P2 — 进入详细设计时可同步处理）

#### P2-1：训练负荷分析与趋势预测未显式设计

**现状**：需求 v0.4 Phase 2 模块 4 提到两项分析能力：
- "训练负荷分析（训练量与水平变化关联）"
- "趋势预测（基于历史数据预测水平变化趋势）"

架构 v2.2 的 `progress_analysis` 模块覆盖了**历史趋势分析**（方向/速率/持续性），但这两项是**前瞻性分析**：
- 训练负荷分析 = 训练量 × 水平变化的关联建模
- 趋势预测 = 基于历史数据外推未来水平

**影响**：Phase 2 交付时缺少这两项功能的后端设计，可能临时拼接。

**建议**：在 `monthly_report` 或 `progress_analysis` 模块中增加：
- 训练负荷关联分析：聚合用户训练频次/分析次数与积分变化，计算相关性
- 趋势预测：基于 technique_trend 时间序列做简单线性外推（非 ML 模型），展示"按当前进步速率，预计 X 周后达标"
- 这两项可作为 Phase 2 月度报告的增强功能，不需要独立模块

#### P2-2：在线订场 Phase 归属跨文档不一致

**现状**：

| 文档 | 位置 | Phase |
|------|------|-------|
| 需求 v0.4 | Phase 4 模块 4 | "[P4 扩展] 球馆在线订场" |
| 前端设计 v2.0 | E3.11 球馆详情 | "[P4] 在线订场"按钮 |
| 架构 v2.2 | §1.3 系统边界 | "球馆在线订场 SaaS（Phase 5 扩展）" |

**影响**：前端在 Phase 4 球馆详情页放了"在线订场"按钮，但架构将其归为 Phase 5 扩展。如果 Phase 4 上线球馆详情页，按钮不可点击或不存在对应后端。

**建议**：统一为 Phase 5。前端 v2.0 E3.11 的"[P4] 在线订场"改为"[P5] 在线订场"或移除，Phase 4 仅展示球馆信息和导航。

#### P2-3：Phase 2-4 API 端点未提供

**现状**：架构 §5.7 仅提供 Phase 1 的 API 端点清单（~60 端点）。Phase 2-4 的模块在模块矩阵中有定义，但缺少 API 端点表。

**影响**：Phase 2-4 开发时需要自行推导 API 设计，可能与架构意图偏离。

**建议**：在进入 Phase 2 详细设计时补充。当前阶段标注为"随 Phase 推进逐步补充"即可，不阻塞 Phase 1 开发。

### 2.3 可延后（P3 — 不阻塞开发）

#### P3-1：WebSocket 时序图中 Authorization 头渲染异常

**位置**：§5.2 第 677 行

**现状**：`Authorization:[REDACTED...` 后跟大量 `]` 字符，是 Mermaid 渲染与脱敏处理冲突导致。

**影响**：文档美观性，不影响理解。

**建议**：改为 `Authorization: Bearer <JWT>` 格式。

---

#### P3-2：PDF 导出功能未设计

**现状**：前端 T2.12 月度训练报告页有"[导出PDF]"按钮，架构未涉及 PDF 生成方案。

**影响**：月度报告导出是用户期望功能，但非核心流程。

**建议**：详细设计阶段补充。可使用 WeasyPrint 或后端渲染 HTML → PDF 方案。

---

#### P3-3：投屏功能未设计

**现状**：前端 C4.5 视频播放器提到"支持投屏到电视"，架构未涉及。

**影响**：投屏是纯前端能力（AirPlay/Chromecast/DLNA），后端无需设计。

**建议**：前端实现时处理，架构无需补充。

---

#### P3-4：实体奖牌未在架构中体现

**现状**：前端设计系统提到 Phase 4"实体奖牌 赛事完赛奖牌（可选购）"，架构无对应模块。

**影响**：实体奖牌是电商/周边商品的小功能，可复用 `ecommerce` 模块。

**建议**：在 `ecommerce` 模块中增加 `merchandise` 子分类即可，不需要独立模块。
