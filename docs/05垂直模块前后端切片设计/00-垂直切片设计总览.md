## 3. 通用约定

### 3.1 后端通用约定

- **统一响应格式**：`{code, message, data, timestamp}`，通过 `app/core/response.py` 的 `success()` / `error()` 包装
- **分页格式**：`{total, page, page_size, items}`，通过 `app/core/pagination.py` 的 `paginate()` 生成
- **异常处理**：统一使用 `AppException(message, code)`，全局处理器返回统一错误格式
- **认证**：JWT Bearer Token，通过 `Depends(get_current_user)` 注入
- **权限守卫**：`get_current_user` → `require_membership(tier)` → `require_creator`
- **Service 方法**：使用 `@staticmethod` 或 `@classmethod`，禁止创建实例
- **Schema 命名**：`{Entity}CreateRequest`、`{Entity}UpdateRequest`、`{Entity}Brief`、`{Entity}Detail`、`Paginated{Entities}`
- **路由注册**：各模块 router 在 `app/api/v1/__init__.py` 中挂载
- **数据库迁移**：使用 Alembic `revision --autogenerate` + `upgrade`
- **测试**：使用 `pytest` + `httpx.AsyncClient`，四类测试用例（Happy Path / Validation / Permission / Business Rule）

### 3.2 前端通用约定

- **组件库**：NutUI React (`@nutui/nutui-react`)
- **状态管理**：Zustand，每个功能域一个 store
- **HTTP 请求**：`frontend/src/services/request.ts` 封装 Taro.request，拦截器自动添加 Token + 刷新
- **路由**：Taro 路由，通过 `app.config.ts` 配置页面路径
- **i18n**：i18next，`useTranslation` Hook，所有用户可见文本使用 `t('key')`
- **设计系统**：色彩 `#E63946`（主色）、`#1D3557`（深蓝）、`#F4A261`（橙黄）等
- **间距**：8px 网格系统
- **全局 CSS 变量**：在 `frontend/src/styles/app.scss` 的 `:root` 中统一定义，各模块 SCSS **禁止** 重复定义：

- **CP-006**：加载状态必须使用 NutUI `<Skeleton>` 骨架屏组件，禁止使用纯文本占位
- **CP-008**：空数据状态必须使用 NutUI `<Empty>` 组件，禁止使用纯文本占位
- **RT-009**：API 枚举字段必须在响应示例或字段说明中标注所有合法值（如 `status` 枚举：`active | expired | grace_period`）

### 3.3 WebSocket 约定

- **连接地址**：`wss://api.pingpongai.com/ws?token={jwt_token}`
- **事件类型**：`connected`、`analysis_progress`、`analysis_complete`、`analysis_failed`、`score_update`、`sync`、`sync_match`、`match_finished`、`notification`、`payment_success`、`badge_unlocked`、`export_completed`、`ping`/`pong`

### 3.5 全局 API 限流配置

后端使用 `slowapi` 实现全局限流，在 `app/main.py` 中全局注册：

```python
# app/main.py
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address
from slowapi.errors import RateLimitExceeded

limiter = Limiter(key_func=get_remote_address, storage_uri="redis://localhost:6379/1")

app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)

# 全局限流规则：
# - 默认: 100 req/min per IP
# - AI 分析创建: 10 req/hour per user
# - 短信发送: 1 req/min per phone (auth 模块已实现)
# - 分享创建: 5 req/day per user (video_analysis 模块已实现)

# 限流装饰器使用示例：
# @limiter.limit("100/minute")
# async def default_endpoint(...): ...

# @limiter.limit("10/hour", key_func=lambda r: r.state.user_id)
# async def create_analysis_task(...): ...
```

> **TS-1 修复说明**：`limiter` 对象应在 `app/core/limiter.py` 中定义并导出，而非直接在 `app/main.py` 中创建。各切片路由通过 `from app.core.limiter import limiter` 导入使用。实现如下：
>
> ```python
> # app/core/limiter.py
> """全局 API 限流配置 — 基于 slowapi (Redis 后端)。"""
> from slowapi import Limiter, _rate_limit_exceeded_handler
> from slowapi.util import get_remote_address
> from slowapi.errors import RateLimitExceeded
> from app.core.config import settings
>
> limiter = Limiter(
>     key_func=get_remote_address,
>     storage_uri=f"redis://{settings.REDIS_HOST}:{settings.REDIS_PORT}/1",
>     default_limits=["100/minute"],
> )
>
> rate_limit_exceeded_handler = _rate_limit_exceeded_handler
> RateLimitExceeded = RateLimitExceeded
> ```
>
> ```python
> # app/main.py (摘录)
> from app.core.limiter import limiter, rate_limit_exceeded_handler, RateLimitExceeded
> app.state.limiter = limiter
> app.add_exception_handler(RateLimitExceeded, rate_limit_exceeded_handler)
> ```

切片中各模块路由需补充 `@limiter.limit()` 装饰器，规则如下：

| 端点类别 | 限流规则 | key_func |

### 3.6 WebSocket 前端重连策略

前端 WebSocket 连接 **必须** 实现指数退避重连，禁止使用固定间隔重连：

```typescript
// frontend/src/hooks/useWebSocket.ts
const RECONNECT_DELAYS = [1, 2, 4, 8, 16]; // 秒，指数退避

function useWebSocket(url: string) {
  const [connected, setConnected] = useState(false);
  const reconnectAttempt = useRef(0);
  const wsRef = useRef<WebSocket | null>(null);

  const connect = useCallback(() => {
    const ws = new WebSocket(url);
    wsRef.current = ws;

    ws.onopen = () => {
      setConnected(true);
      reconnectAttempt.current = 0;
      // 重连后拉取断连期间消息
      onReconnect();
    };

    ws.onclose = () => {
      setConnected(false);
      // 指数退避重连: 1→2→4→8→16s
      const delay = RECONNECT_DELAYS[Math.min(reconnectAttempt.current, RECONNECT_DELAYS.length - 1)];
      reconnectAttempt.current++;
      setTimeout(connect, delay * 1000);
    };

    ws.onmessage = (event) => { /* ... */ };

    // 30s 心跳
    const heartbeat = setInterval(() => {
      if (ws.readyState === WebSocket.OPEN) {
        ws.send(JSON.stringify({ event: 'ping' }));
      }
    }, 30000);

    return () => clearInterval(heartbeat);
  }, [url]);

  useEffect(() => {
    connect();
    return () => wsRef.current?.close();
  }, [connect]);

  return { connected, ws: wsRef.current };
}
```

要点：
- 指数退避重连：1 → 2 → 4 → 8 → 16s，最大 5 次
- 30s 心跳 ping，维持连接活性
- 重连成功后调用 `onReconnect()` 拉取断连期间错过的消息
- **禁止** 使用固定间隔重连

### 3.8 无障碍设计规范

- 所有 `<Button>` 组件应添加 `aria-label`（尤其图标按钮）
- 所有 `<View onClick>` 应添加 `role="button"` + `aria-label` + `accessible` 属性（`accessible={true}` 使元素可被读屏器聚焦，与 `role="button"` 配合确保点击区域的无障碍可操作性）
- 所有 `<Input>` 应添加 `aria-label`（与 placeholder 一致）
- SVG 图表应添加 `role="img"` + `aria-label`
- 图片列表场景应使用 `lazy-load` 属性或 `IntersectionObserver` 按需加载

**WCAG AA 最佳实践（开发阶段统一实现）：**

- **颜色对比度**：WCAG AA 要求文字与背景对比度 ≥ 4.5:1（大文字 ≥ 3:1）。设计系统中 `--color-text-secondary`（#6C757D）在白色背景上对比度约 4.8:1 ✅，但需在暗色背景上验证；暗色主题或其他自定义背景上的文字色需逐一校验对比度，不达标时调整色值
- **焦点可见性**：所有可交互元素（`<Button>` / `<Input>` / `<View onClick>`）必须有可见的 focus 样式（focus 时显示 `outline` 或 `border` 高亮），键盘导航用户依赖此反馈定位当前元素；禁止全局移除 `outline` 除非提供等效的替代焦点样式
- **触摸目标尺寸**：遵循 WCAG 2.2 SC 2.5.8 要求，触摸目标最小 24×24 CSS 像素（AA 级）。`<Button>` 和 `<View onClick>` 的最小可点击区域尺寸应 ≥ 24px，图标按钮尤需注意；若视觉尺寸不足，可通过 padding 扩大命中区域
- **动态内容通知**：使用 `aria-live="polite"` 通知屏幕阅读器动态内容更新，适用场景包括 WebSocket 推送的通知消息、记分牌实时比分变化、分析进度条状态更新等；频繁更新（如实时比分）使用 `polite` 等级避免打断用户当前操作，紧急错误可使用 `aria-live="assertive"`

- 注：Phase 1 切片为设计文档，上述 ARIA 属性及 WCAG AA 规范将在开发阶段统一实现

> **R18-P3-16 修复（已在 R18 落地）**：ARIA 属性未实现的设计决策说明。原 R18 推迟原因为"开发阶段统一实现"，现显式验证：
> - **规范完整性**：§3.8 已覆盖 ARIA 五大场景（Button/View-onClick/Input/SVG/lazy-load）+ WCAG AA 四大维度（颜色对比度/焦点可见性/触摸目标/动态内容通知），与 Taro 4 + NutUI 组件库的无障碍 API 完全对应
> - **设计阶段职责**：Phase 1 切片为设计文档，主要展示组件结构、数据流、状态管理与样式规范；ARIA 属性属实现层细节，在开发阶段基于 §3.8 规范统一添加
> - **实施时机**：Phase 1 开发启动后，每个切片实现 PR 必须包含 ARIA 属性自检清单（5 项 ARIA + 4 项 WCAG AA），代码审查时逐项确认
