## 二、P0 级问题（5 项 — 阻断性，必须立即修复）

### P0-1：POINTS_RULES 字典语法错误 — training_session 键被注释吞没
- **文件**：`09-gamification/backend.md` L415
- **问题**：第三轮 P0-3 修复引入的回归。`"streak_30": 100,` 后的 `#` 注释吞没了 `"training_session": 5,` 和字典闭合 `}`，导致：
  1. training_session 键实际不在 POINTS_RULES 中
  2. Python SyntaxError（字典未闭合）
  3. 整个 gamification 模块无法加载
- **影响**：积分触发链断裂，add_points 返回 0，训练单完成不加分
- **建议**：将 training_session 拆到独立行

### P0-2：cancel-deletion 端点在切片中完全缺失
- **文件**：`02-user/backend.md`（API 设计 §3.10 L880 已定义）
- **问题**：API 设计 v1.3 §3.10 定义了 `POST /users/account/cancel-deletion`（72h 注销撤销），但 02-user/backend.md 的 8 个路由中无此端点
- **影响**：用户注销后无法通过 API 撤销，72h 冷静期机制不可用
- **建议**：在 02-user/backend.md 新增路由 + Service 方法

### P0-3：04-scoring 路由名称与总览不匹配
- **文件**：`04-scoring/frontend.md` vs `00-垂直切片设计总览.md` app.config.ts
- **问题**：scoring 定义 `pages/scoring/scoreboard/index` 和 `pages/scoring/match-list/index`，但总览注册的是 `pages/scoring/match/index`
- **影响**：记分页和比赛列表页 404
- **建议**：统一路由名称

### P0-4：02-user 三个子页面路由未注册
- **文件**：`02-user/frontend.md` vs `00-垂直切片设计总览.md`
- **问题**：`pages/user/edit`、`pages/user/big-data`、`pages/user/rating-history` 在 app.config.ts 中不存在，且缺少 `/index` 后缀
- **影响**：用户编辑页、大数据页、积分历史页 404
- **建议**：在 app.config.ts 补充 3 个路由 + 添加 /index 后缀

### P0-5：MembershipTierConfig 缺少 price_quarterly_cents 字段
- **文件**：`10-membership/backend.md` MembershipTierConfig 模型
- **问题**：MEMBERSHIP_TIERS 常量定义了 `pricing: { monthly, quarterly, yearly }`，但 MembershipTierConfig 模型缺少 `price_quarterly_cents` 字段
- **影响**：季卡价格无法持久化到数据库
- **建议**：在 MembershipTierConfig 模型补充 `price_quarterly_cents: Mapped[int]`

## 七、关键风险点

### 1. 回归风险
**P0-1 POINTS_RULES 语法错误**是第三轮 P0-3 修复引入的回归。原始修复将 `training_session: 5` 添加到 POINTS_RULES 字典，但由于格式化问题，键被注释吞没。这表明**修复后的验证机制不足**，需要在每次修复后执行语法检查。

### 2. DB §5 滞后风险
10 项 P1 问题集中在 DB 设计 §5 SQLAlchemy 代码块滞后于 §2 DDL 定义。这些直接影响 Alembic 迁移脚本的正确性，可能导致生成的数据库 schema 与设计不符。

### 3. 路由一致性风险
P0-3 和 P0-4 暴露了前端路由定义与 app.config.ts 注册之间的系统性脱节。建议在开发阶段引入路由一致性检查脚本。

### 4. 事务完整性风险
P1-X1（session 已关闭）和 P1-X2（缺 commit）表明跨模块调用的事务边界设计需要重新审视。
