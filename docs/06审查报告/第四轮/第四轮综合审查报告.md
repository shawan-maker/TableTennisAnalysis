## P0 级问题（阻断实现）

### P0-1: POINTS_RULES `training_session` 写入注释行导致字典未闭合

| 项 | 内容 |
|---|------|
| **涉及文件** | `06垂直模块前后端切片设计/09-gamification/backend.md` L415 |
| **维度** | A. 业务逻辑一致性 |
| **问题描述** | L415 原文为：`"streak_30": 100,  # 连续打卡 30 天额外奖励        "training_session": 5,  # 完成训练    }`。`"training_session": 5,` 和字典闭合符 `}` 均出现在 `#` 注释之后，属于注释内容而非 Python 代码。这导致：(1) `training_session` 不在 POINTS_RULES 字典中；(2) 字典缺少闭合 `}`，若直接复制为 .py 文件将产生 SyntaxError。 |
| **根因** | 第三轮 P0-3 修复要求在 POINTS_RULES 中添加 `"training_session": 5`，但修复执行时将新条目追加到了 `streak_30` 行的注释之后，未另起一行。 |
| **影响** | training_advice 切片 L1106 调用 `add_points(db, user_id=user_id, event_type="training_session", ref_id=session_id)` 时，`POINTS_RULES.get("training_session", 0)` 返回 0 分，训练单完成无法获得积分。 |
| **修复建议** | 将 L415 拆分为三行：|
| | ```python |
| |         "streak_30": 100,  # 连续打卡 30 天额外奖励 |
| |         "training_session": 5,  # 完成训练 |
| |     } |
| | ``` |

## P2 级问题（应在实现中修复）

### P2-1: MockRedis expire/setex/ttl 实现不完整

| 项 | 内容 |
|---|------|
| **涉及文件** | `06垂直模块前后端切片设计/13-infrastructure/conftest.py.md` L182（setex）、L194（expire）、L197（ttl） |
| **维度** | D. 测试策略 |
| **问题描述** | MockRedis 的 `expire` 为空操作（no-op），`setex` 不设置真实 TTL，`ttl` 固定返回 300 秒。membership 切片的 `consume_analysis_quota` 依赖 `incr` + `expire` + `decr` 组合实现每日额度控制。测试中 `expire` 不生效导致额度计数器不会自动过期，测试可能误通过（额度永远不会重置为 0）。 |
| **修复建议** | MockRedis 内部维护 `{key: expire_at_timestamp}` 字典。`expire(key, seconds)` 设置 `expire_at = now + seconds`；`ttl(key)` 返回 `max(0, expire_at - now)`；`setex(key, seconds, value)` 等价于 `set(key, value)` + `expire(key, seconds)`。 |

### P2-2: data_dashboard `func.cast(Boolean, Integer)` 缺少 Integer 导入

| 项 | 内容 |
|---|------|
| **涉及文件** | `06-data_dashboard/backend.md` L518（`func.cast(MatchRecord.is_win, Integer)`）、L727 注释 |
| **维度** | C. 性能优化 / 代码质量 |
| **问题描述** | Service 代码中使用 `func.cast(MatchRecord.is_win, Integer)` 进行布尔到整数的聚合转换，但文件 import 部分仅导入 `from sqlalchemy import select, func, and_`，未导入 `Integer`。L727 注释也提到此问题。 |
| **修复建议** | 在 import 中添加 `Integer`：`from sqlalchemy import select, func, and_, Integer`。或改用 `func.sum(func.case((MatchRecord.is_win.is_(True), 1), else_=0))` 避免类型转换。 |

### P2-4: 审计日志保留策略与 PIPL 要求矛盾

| 项 | 内容 |
|---|------|
| **涉及文件** | `04详细设计/04-数据库详细设计.md` §2.31 audit_log 表（无保留策略）；`03系统架构/01-系统架构设计.md` §11.4 L2011（操作日志 6 个月） |
