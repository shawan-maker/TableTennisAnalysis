### P2-1：DB 连接池参数缺失

| 项目 | 内容 |
|------|------|
| **问题描述** | SQLAlchemy async engine 的连接池参数（`pool_size`、`max_overflow`、`pool_recycle`、`pool_pre_ping`）在架构文档和所有切片文件中均未配置。架构文档 L3088 提到监控"连接池使用率 > 80%"但未定义池配置参数本身。 |

| **验证方法** | grep `pool_size` / `pool_recycle` 在 database.py 切片或架构文档中应有匹配 |

### P2-2：日志轮转配置缺失

| 项目 | 内容 |
|------|------|
| **问题描述** | 三层日志均缺少轮转机制：① 应用层 structlog 输出到 stdout，但 Docker Compose 未配置 `json-file` 驱动的 `max-size`/`max-file`；② Nginx access.log/error.log 写入卷但无 logrotate；③ Docker 容器默认 `json-file` 驱动无大小限制 |
| **影响范围** | 生产环境长期运行日志无限增长，最终填满磁盘导致服务崩溃 |
| **修复建议** | ① Docker Compose 各服务增加 `logging: { driver: json-file, options: { max-size: "50m", max-file: "3" } }`；② logging.md 补充生产环境日志收集策略说明（stdout → Docker json-file → 限制大小 / 或对接 ELK/Loki） |
| **验证方法** | grep `max-size` / `max-file` / `logging:` 在 docker.md 中应有匹配；grep `RotatingFileHandler` 或 `logrotate` 在 logging.md 中应有匹配 |
