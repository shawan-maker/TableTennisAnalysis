## 二、发现问题

### P0（严重 — 运行时崩溃 / 语法错误）

#### P0-1：gamification _auto_checkin streak_30 分支参数顺序错位

- 文件：09-gamification/backend.md
- 位置：L692-695
- 方法签名：_add_points(db: AsyncSession, user_id: int, event_type: str, points: int, ref_id: Optional[int] = None)（L632-635）
- 错误调用：_add_points("streak_30", user_id, db)
  - "streak_30"(str) 被传入 db 形参
  - user_id(int) 正确
  - db(AsyncSession) 被传入 event_type 形参
  - 缺失 points 参数
- 正确调用（同文件 L535 对比）：_add_points(db, user_id, "streak_30", bonus)
- 影响范围：add_points 公开方法在 L570-572 调用 _auto_checkin，意味着任何外部模块（scoring/match_data/training_advice/ai_pipeline）触发积分时，如果用户恰好连续打卡 30 天，将触发此崩溃。
- 根因：第四轮 P0-1 修复 POINTS_RULES 语法错误后，_auto_checkin 方法中的 streak_30 分支未被同步修正，属回归遗漏。
- 修复建议：将 L693-695 改为 _add_points(db, user_id, "streak_30", GamificationService.POINTS_RULES["streak_30"])

#### P0-2：auth refresh_token 方法结构断裂

- 文件：01-auth/backend.md
- 位置：L427-506
- 问题描述：refresh_token 方法定义于 L427，方法体在 L428-448。PIPL-001 修复时，在 L450-499 之间插入了 CURRENT_POLICY_VERSION 类常量、check_consent 方法（L455）、record_consent 方法（L478），导致原本属于 refresh_token 的 return RefreshResponse(...) 语句（L502-506）物理脱离了方法体，变成孤立代码。
- 代码结构：
  L427  async def refresh_token(...) -> RefreshResponse:
  L428-448  方法体（无 return）
  L450  # --- PIPL-001 修复 ---
  L452  CURRENT_POLICY_VERSION = "1.0"
  L454-475  async def check_consent(...)
  L477-499  async def record_consent(...)
  L502-506  return RefreshResponse(...)  <- 孤立，不在任何方法内
  L508  async def logout(...)
- 影响：refresh_token 方法不返回 RefreshResponse（隐式返回 None），或 Python 在导入时报 SyntaxError: return outside function。用户刷新 token 功能完全不可用。
- 根因：PIPL-001 隐私同意记录功能插入时，未将 return RefreshResponse(...) 保持 在 refresh_token 方法内部。
- 修复建议：将 L502-506 的 return RefreshResponse(...) 移回 refresh_token 方法体内（L448 之后、L450 注释之前）。

### P1（高 — 缺失实现 / 跨模块断裂）

#### P1-1：MatchDataService.create_record_from_scoring 方法未定义

- 调用方：04-scoring/backend.md L942
  await MatchDataService.create_record_from_scoring(db, match_id=match.id, user_id=match.user_id)
- 被调用方：05-match_data/backend.md — MatchDataService 类定义了 create_record、list_records、get_detail、update_record、_trigger_gamification 共 5 个方法，但未定义 create_record_from_scoring。
- 总览跟踪：00-垂直切片设计总览.md L544 标记 "OK scoring 增加 create_record_from_scoring 调用"，但仅添加了调用点，未在 match_data 切片中实现方法。
- 影响：scoring 模块 finish_match 调用此方法时会抛 AttributeError，记分牌比赛结束后无法自动创建 match_record。
- 修复建议：在 05-match_data/backend.md 的 MatchDataService 类中新增 create_record_from_scoring 方法，接收 (db, match_id, user_id)，从 scoring 的 ScoreRecord 表读取比分明细并转换为 MatchRecord。

### P2（中 — 一致性 / 规范偏差）

#### P2-1：gamification _auto_checkin 中 checkin/streak_7 调用缺少 ref_id

- 文件：09-gamification/backend.md L683-690
- 描述：_add_points 签名为 (db, user_id, event_type, points, ref_id=None)，checkin 和 streak_7 调用未传 ref_id 参数。由于 ref_id 有默认值 None，不会报错，但与其他 _add_points 调用风格不一致。

#### P2-2：data_dashboard Schema 使用 Response 后缀而非 Brief/Detail

- 文件：06-data_dashboard/backend.md
- 描述：使用 OverviewResponse/WinRateTrendResponse/TechniqueStatsResponse 等 Response 后缀。
- 判定：总览 MA-2 已说明 dashboard 不建独立 Model，属只读聚合端点，Response 后缀为合理设计变体。计为 P2 级规范偏差记录，不要求修改。

### P3（低 — 优化建议）

#### P3-1：BadgeService._add_points 使用非 POINTS_RULES 的事件名

- 文件：09-gamification/backend.md L846-848
- 描述：_add_points(db, user_id, f"badge_{definition.id}", definition.points_reward) 中 event_type 为 f"badge_{definition.id}"，不在 POINTS_RULES 中。由于直接调用私有 _add_points（绕过公开 add_points 的 POINTS_RULES 查找），功能正确，但事件名不在统一规则表中，不利于审计追溯。
