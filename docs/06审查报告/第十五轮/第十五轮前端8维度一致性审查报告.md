### 3.2 检查项 #10：useMatchSync 是否正确使用 useWebSocket 的 sendMessage/isConnected/onMessage

**位置**：04-scoring/frontend.md L359-395

**API 使用层面**：✅ 三项 API 均正确调用——`sendMessage` 用于发送 join 消息，`isConnected` 用于守卫连接就绪逻辑，`onMessage` 用于注册监听器并在 cleanup 中取消订阅。

**但发现 P0 级字段名不匹配 Bug**：

| 问题 | 位置 | 详情 |
|------|------|------|
| **P0-1** | L376 | `if (msg.type === 'score_update')` — 服务器消息使用 `event` 字段（见 useWebSocket handleMessage L230 `switch (msg.event)`），但此处检查 `msg.type`，永远不匹配 |
| **P0-2** | L380 | `if (msg.type === 'sync_match')` — 同样的 `type` vs `event` 字段名错误 |
| **P0-3** | L366 | `sendMessage(JSON.stringify({ type: 'join', room: ... }))` — 出站消息使用 `type` 字段，但 useWebSocket 心跳出站消息使用 `event` 字段（L273 `{ event: 'ping' }`），协议约定不一致 |

**影响**：useMatchSync 的实时比分同步功能完全失效——来自其他设备的 `score_update` 事件永远不会被处理，`sync_match` 全量同步也不会触发。虽然 useWebSocket 内部 handleMessage 会通过 `Taro.eventCenter.trigger('score_update', ...)` 转发事件，但 useMatchSync 未监听 eventCenter，而是通过 onMessage 直接监听（且字段名错误），导致消息链断裂。

**证据链**：
1. 服务器发送 `{"event":"score_update","data":{...}}`（由 useWebSocket L230 `switch (msg.event)` 可推断）
2. useMatchSync L375 `JSON.parse(event.data)` 得到 `msg`
3. L376 检查 `msg.type`（值为 `undefined`）≠ `'score_update'` → 永不进入分支
4. 比分不更新，多设备同步失效

**对比验证**：
- useBadgeUnlock（09-gamification L1048）使用 `data.event === 'badge_unlocked'` → ✅ 字段名正确
- useWebSocket handleMessage（L230）使用 `switch (msg.event)` → ✅ 字段名正确
- 仅 useMatchSync 使用 `msg.type` → ❌ 唯一的异常
