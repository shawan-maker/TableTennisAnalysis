### P0-1：PipelineStep 模型在 video_analysis 中未定义

**文件**：`13-infrastructure/ai_pipeline.md` L66-70 + `03-video_analysis/backend.md` L1398

**问题**：ai_pipeline 切片 L66 声明"ai_pipeline 模块直接 import 复用 `app/models/video_analysis.py` 中已定义的 `VideoTask`、`PipelineStep`、`AnalysisReport` 表"，L70 执行 `from app.models.video_analysis import VideoTask, PipelineStep, AnalysisReport`。

但 video_analysis 切片的验证清单 L1398 明确列出 Model 仅 5 个：`FileRecord, VideoTask, AnalysisReport, FeedbackRecord, ShareRecord`。**PipelineStep 从未在 video_analysis 中定义**。

ai_pipeline 在 L879-884 使用 `PipelineStep(task_id=..., step_number=..., step_name=..., status=...)` 构造对象，字段引用 `task_id`/`step_number`/`step_name`/`status`/`duration_ms`/`step_result`/`error_message`/`started_at`/`completed_at`（L77-78），但这些字段只有注释描述，没有 SQLAlchemy Model 定义。

**影响**：`from app.models.video_analysis import PipelineStep` 会触发 `ImportError`，ai_pipeline 模块无法启动。

**修复建议**：在 `03-video_analysis/backend.md` Model 定义区新增 `PipelineStep` 类：

```python
class PipelineStep(Base):
    __tablename__ = "pipeline_step"
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    task_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("video_task.id"), nullable=False)
    step_number: Mapped[int] = mapped_column(Integer, nullable=False)
    step_name: Mapped[str] = mapped_column(String(64), nullable=False)
    status: Mapped[str] = mapped_column(String(20), default="pending")  # pending/running/completed/failed
    duration_ms: Mapped[Optional[int]] = mapped_column(Integer, nullable=True)
    step_result: Mapped[Optional[dict]] = mapped_column(JSONB, nullable=True)
    error_message: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    started_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    completed_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
```

### P0-2：consume_analysis_quota 方法残留重复 docstring 文本 + 孤立三引号

**文件**：`10-membership/backend.md` L538-544

**问题**：第十四轮修复 P2-DEAD-01 时在 L538 添加了 TODO 注释 `# TODO: Phase 2 统一额度管理...`，但 L539-543 残留了 docstring 内容的裸文本副本（与 L532-536 的 docstring 内容重复），L544 有孤立的 `"""`。

```
L531:        """              ← docstring 开始
L532-536:    消耗一次分析额度...
L537:        """              ← docstring 结束
L538:        # TODO: ...       ← 注释（正确）
L539-543:    消耗一次分析额度...  ← 裸文本！不在字符串内
L544:        """              ← 孤立三引号，开启未闭合的字符串
```

### P1-1：gamification 模块 date.today() 未统一为 CST 时区

**文件**：`09-gamification/backend.md` L506, L611, L669

**问题**：gamification 模块 3 处使用 `date.today()`（naive，依赖服务器本地时区）：

| 位置 | 方法 | 代码 |
|------|------|------|
| L506 | `checkin` | `today = date.today()` |
| L611 | `_update_streak` | `today = date.today()` |
| L669 | `_auto_checkin` | `today = date.today()` |

其他模块已统一使用 `datetime.now(timezone(timedelta(hours=8))).date()`（CST 显式时区）。当服务器时区为 UTC 时（如 Docker 默认），UTC 23:00（CST 次日 07:00）时 gamification 写入前一天的日期，而 video_analysis/membership 写入当天日期，导致：

1. **打卡日期错位**：用户在 CST 07:00 触发分析自动打卡，CheckInRecord.checkin_date 写入前一日
2. **连续打卡断裂**：Redis `gamification:streak:last_date:{user_id}` 写入前一日，与实际打卡日期不一致
3. **额度/打卡日期不匹配**：video_analysis 的 quota Key 用 CST 日期，gamification 的 checkin_date 用 UTC 日期

**修复建议**：将 3 处 `date.today()` 改为：

```python
from datetime import datetime, timezone, timedelta
tz_cst = timezone(timedelta(hours=8))
today = datetime.now(tz_cst).date()
```
