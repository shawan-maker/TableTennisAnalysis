#### 判定

> **P1 — 架构 §5.7 端点清单不完整，缺失 6 个业务端点 + 17 个 admin 端点**
>
> 架构 §5.7 标题为「Phase 1 核心 API 端点清单」，虽注明"核心"，但实施计划 Sprint 端点总数 96 = 79 业务 + 17 admin，与 API 设计完全一致。架构作为系统设计的权威来源，其 §5.7 应至少覆盖所有业务端点或明确引用 API 设计文档完整清单。当前缺失的 6 个业务端点中有 2 个涉及 PIPL 合规（consent 端点）、1 个涉及退款流程（refund 端点），均为关键业务端点，不宜遗漏。
>
> **建议修复**：在架构 §5.7 中补充缺失的 6 个业务端点行；新增 admin 模块端点段落或添加引用说明「admin 端点详见 API 设计 §19」。
