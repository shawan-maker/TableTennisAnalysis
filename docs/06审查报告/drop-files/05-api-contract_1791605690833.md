# API 契约设计模板

> **用途**：新增/修改 API 端点时，按本模板定义完整的请求/响应契约。
> AI 在生成 API 代码前，**必须先阅读本文件 + `00-common-conventions.md`**。

---

## 1. 全局规范（引用 00-common-conventions.md）

以下规范在 `00-common-conventions.md` 中详细定义，此处仅列要点：

| 规范 | 要点 | 详见 |
|------|------|------|
| 响应信封 | 所有端点返回 `{ code, message, data, timestamp }`，通过 `success()` 包装 | 00 §4 |
| 分页 | `Paginated[T]` 结构：`{ total, page, page_size, items }` | 00 §5 |
| Auth 依赖链 | `get_current_active_user` → Service 层权限校验 | 00 §6 |
| 错误处理 | `raise AppException(message, code)`，禁止手动构造错误 dict | 00 §7 |
| 枚举同步 | 后端 `enums.py` ↔ 前端 `constants.js` 同步更新 | 00 §8 |

## 2. 单端点契约模板

每个端点必须包含以下完整信息。AI 生成代码时应以此作为规格说明。

### 模板

```
### {METHOD} {path}

**描述**：一句话说明端点功能
**权限**：viewer / editor / owner / super_admin
**标签**：OpenAPI tag 名称

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 描述 |
|------|------|------|------|------|
| ... | path/query/body | ... | Y/N | ... |

#### Request Body（POST/PATCH/PUT 时填写）

\`\`\`json
{
  "field": "value"
}
\`\`\`

#### Response Body

\`\`\`json
{
  "code": 200,
  "message": "success",
  "data": { },
  "timestamp": "2025-01-01T00:00:00.000000Z"
}
\`\`\`

#### 业务规则
1. 规则一
2. 规则二

#### 错误情况

| HTTP | 条件 | 消息 |
|------|------|------|
| 400 | ... | ... |
| 404 | ... | ... |
```

```

**描述**：获取单个测试任务详情
**权限**：viewer（项目查看者及以上）
**标签**：测试管理-任务

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 描述 |
|------|------|------|------|------|
| task_id | path | int | Y | 任务 ID |

#### Response Body

\`\`\`json
{
  "code": 200,

    "project_id": 10,
    "module_id": null,
    "environment_id": 3,

1. 返回任务完整字段，不含关联的套件/用例列表

| HTTP | 条件 | 消息 |
|------|------|------|
| 403 | 用户无权访问该项目 | 无权访问该项目 |
```

## 4. 查询参数约定

### 分页

| 参数 | 类型 | 默认值 | 约束 | 说明 |
|------|------|--------|------|------|
| `page` | int | 1 | ge=1 | 页码 |
| `page_size` | int | 20 | ge=1, le=100 | 每页条数。部分端点上限 200 |

### 筛选

直接使用字段名作为 query param，值为枚举字符串：

```
GET /tasks?project_id=10&status=pending&type=api
```

- 多个同名字段用逗号分隔表示 OR：`?status=pending,running`
- 空值或不传表示不过滤

### 搜索

统一使用 `q` 参数进行文本模糊搜索：

```
GET /tasks?project_id=10&q=回归
```

搜索范围由 Service 层决定（通常搜 name + description）。

### 排序

统一使用 `sort` 参数：

```
GET /tasks?project_id=10&sort=-created_at          # 按创建时间降序
GET /tasks?project_id=10&sort=name                  # 按名称升序
GET /tasks?project_id=10&sort=-status,created_at    # 多字段排序
```

- `-` 前缀表示降序（DESC），无前缀为升序（ASC）
- 默认按 `-created_at` 降序（最新优先）

## 5. 权限标注约定

契约文档中的权限级别映射到 `service/core/deps.py` 的实际函数：

| 契约标注 | deps.py 函数 | 含义 |
|---------|-------------|------|
| viewer | `require_project_viewer(project_id, user)` | 项目查看者及以上（viewer/editor/owner/super_admin） |
| editor | `require_project_editor(project_id, user)` | 项目编辑者及以上（editor/owner/super_admin） |
| owner | `require_project_owner_or_super_admin(project_id, user)` | 项目管理员或超级管理员 |
| super_admin | `get_current_super_admin(user)` | 仅超级管理员 |
| logged_in | `get_current_active_user(user)` | 任何已登录且激活的用户 |

**重要原则**：
- API 路由层只注入 `user: User = Depends(get_current_active_user)`
- **权限校验在 Service 层完成**，不在路由函数中调用 require_* 函数
- Service 方法第一行调用对应的权限检查函数

```python
# ✅ 正确：路由只注入 user
@router.get("/{task_id}")
async def get_task(task_id: int, user: User = Depends(get_current_active_user)):
    data = await TaskService.get_detail(user, task_id)
    return success(data=data)

# ❌ 错误：路由中做权限校验
@router.get("/{task_id}")
async def get_task(
    task_id: int,
    project: Project = Depends(require_project_viewer),  # 不要这样做
):
    ...
```

## 6. SSE 流式端点模板

用于 AI 生成等长耗时操作。客户端通过 EventSource 或 fetch + ReadableStream 消费。

### 端点定义

```
### POST /ai-generation/functional/sessions/{session_id}/messages

**描述**：发送消息并接收 AI 流式响应
**权限**：editor
**Content-Type 响应**：text/event-stream

#### Request Body

\`\`\`json
{
  "content": "请根据这个需求生成测试用例",
  "message_type": "text"
}
\`\`\`

#### SSE Event 格式

\`\`\`
event: start
data: {"session_id": 1, "message_id": 42}

event: text_delta
data: {"content": "## 测试"}

event: text_delta
data: {"content": "用例\n\n1. "}

event: progress
data: {"step": "generating", "progress": 0.6}

event: complete
data: {"message_id": 42, "total_tokens": 1500}

event: error
data: {"message": "LLM 调用超时", "code": 504}
\`\`\`
```

### 后端实现模式

```python
from fastapi.responses import StreamingResponse

@router.post("/sessions/{session_id}/messages")
async def post_message(
    session_id: int,
    body: AgentMessageRequest,
    user: User = Depends(get_current_active_user),
):
    """发送消息并返回 SSE 流式响应。"""
    stream = FunctionalAgentService.stream_message(user, session_id, body)
    return StreamingResponse(stream, media_type="text/event-stream")
```

### SSE Event 类型规范

| event 类型 | 必选 | data 内容 | 说明 |
|-----------|------|----------|------|
| `start` | Y | `{ session_id, message_id }` | 流开始，标识本次生成的消息 ID |
| `text_delta` | Y | `{ content: "增量文本" }` | 文本增量块，客户端拼接显示 |
| `progress` | N | `{ step, progress }` | 进度通知，progress 为 0~1 浮点数 |
| `tool_call` | N | `{ tool_name, args }` | AI 调用工具通知 |
| `tool_result` | N | `{ tool_name, result }` | 工具执行结果 |
| `complete` | Y | `{ message_id, total_tokens }` | 流正常结束 |
| `error` | Y(异常时) | `{ message, code }` | 流异常终止 |

### 前端消费模式

```javascript
import { postEventStream } from '@/utils/sse'

await postEventStream(
  `/api/v1/ai-generation/functional/sessions/${sessionId}/messages`,
  { content: message },
  {
    onEvent(event, data) {
      if (event === 'text_delta') appendText(data.content)
      if (event === 'complete') finishGeneration(data)
      if (event === 'error') handleError(data)
    }
  }
)
```

## 8. 反幻觉约束（AI 必读）

以下约束在生成 API 代码时 **必须严格遵守**：

### 响应约束
- **ALL** 端点返回值 **MUST** 通过 `success()` 包装，**NEVER** 返回裸 dict/list
- **ALL** 列表端点 **MUST** 使用 `Paginated[T]` 结构，**NEVER** 自定义分页格式
- **NEVER** 手动构造 `{ "code": ..., "message": ... }` 错误响应 dict

### 参数约束
- **ALL** 变更类端点（POST/PATCH/PUT/DELETE）**MUST** 接受 `user: User = Depends(get_current_active_user)` 作为最后一个参数
- 分页参数 **MUST** 使用 `Query(default=..., ge=1)` 校验
- **NEVER** 在路由函数中直接操作数据库，**ALL** 业务逻辑委托给 Service 层

### 权限约束
- 权限校验 **MUST** 在 Service 层完成，**NEVER** 在 API 路由中调用 `require_project_*` 函数
- 路由层只注入 `get_current_active_user`，由 Service 方法内部调用对应的权限检查
- **NEVER** 跳过权限检查，即使是"内部接口"

### HTTP 方法约束
- `GET` = 读取，**NEVER** 有副作用
- `POST` = 创建 / 批量操作 / 状态流转
- `PATCH` = 部分更新（只传变更字段）
- `PUT` = 全量替换
- `DELETE` = 删除
- **NEVER** 用 GET 执行写操作，**NEVER** 用 POST 做纯查询

### 导入约束
- API 文件只导入：`fastapi`, `deps`, `response.success`, Schemas, Service, `User` model
- **NEVER** 在 api.py 中导入 Tortoise Model 进行直接查询
- **NEVER** 在 api.py 中定义 Pydantic Schema（放 schemas.py）
- **NEVER** 在 api.py 中编写业务逻辑（放 *_service.py）

### 路由注册约束
- 每个子模块的 router 使用 `APIRouter(prefix="/xxx", tags=["中文标签"])`
- 聚合路由在模块根 `api.py` 中通过 `include_router` 挂载
- 所有路由最终通过 `service/router.py` 挂载到 `/api/v1` 前缀下
