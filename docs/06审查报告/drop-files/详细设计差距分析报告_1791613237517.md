## 三、需修复问题（P0 — 阻塞 Phase 1 开发）

### P0-1：API 错误码严重缺失（54/64 端点无错误码）

**位置**：`05-API详细设计.md`

**现状**：64 个 Phase 1 端点中仅 10 个（15.6%）有错误码表，54 个完全没有。缺失涉及全部 12 个模块，包括支付回调 `POST /payment/notify`、所有列表端点、所有 GET 详情端点等核心接口。

| 模块 | 有错误码端点数 | 无错误码端点数 |
|------|-------------|-------------|
| 认证 | 4 | 4 |
| 用户 | 1 | 4 |
| 视频分析 | 3 | 8 |
| 记分牌 | 2 | 5 |
| 数据看板 | 0 | 5 |
| 比赛数据 | 0 | 3 |
| 训练 | 0 | 6 |
| 进度分析 | 0 | 6 |
| 游戏化 | 1 | 3 |
| 会员 | 0 | 3 |
| 支付 | 0 | 3 |
| 通知 | 0 | 3 |

**影响**：前端无法编写错误处理逻辑，后端无法统一异常响应标准，联调时沟通成本极高。

**建议**：
1. 新增"全局通用错误码表"（401 未认证 / 403 权限不足 / 404 资源不存在 / 422 参数校验失败 / 429 限流 / 500 服务端错误）
2. 每个端点至少列出业务特定错误码（如 40901 免费额度耗尽、40401 报告不存在、40902 比赛状态不允许操作）
3. 优先修复支付回调、记分牌、视频分析三个核心模块

### P1-4：支付回调契约严重不完整

**位置**：`05-API详细设计.md` §12.3

**现状**：`POST /payment/notify` 是微信支付异步回调端点，但：
- 无 Request Body 格式（微信 V3 回调的原始 JSON 结构：`resource.ciphertext` 加密数据）
- 无 Request Header 说明（`Wechatpay-Signature` / `Wechatpay-Serial` / `Wechatpay-Nonce` / `Wechatpay-Timestamp`）
- 无验签流程描述
- 无 Response 格式（应返回 `{"code": "SUCCESS", "message": "成功"}`）
- 无错误码（验签失败 400 / 解密失败 400 / 订单不存在 404）
- 无幂等处理说明（同一回调多次发送时的处理）

**影响**：支付回调是核心商业流程，契约不完整会导致支付状态不一致。

**建议**：补充完整的微信支付 V3 回调契约，包含请求头/请求体/验签流程/解密流程/响应格式/幂等处理/错误码。
