## 3. 维度②：Redis Key 命名规范

### 3.1 检查方法

对全部切片中 Redis Key 的定义和使用进行交叉比对，检查：
- Key 前缀命名是否符合架构 §9 Redis 设计规范
- 占位符变量名是否统一（`{uid}` vs `{user_id}`）
- 同一业务 Key 在不同模块中的格式是否一致
- 日期格式是否统一

### 3.2 发现

#### P0-REDIS-01：免费额度 Key 日期格式不一致，导致额度退还失败

| 项目 | 内容 |
|------|------|
| 严重度 | **P0（严重 — 运行时功能失败）** |
| 涉及文件 | `10-membership/backend.md` L371, L472, L542, L628 vs `13-infrastructure/ai_pipeline.md` L929-930 |
| 问题描述 | membership 写入额度 Key 时使用 `today.isoformat()`，日期格式为 `2026-10-13`（含连字符）；ai_pipeline 退还额度时使用 `today.strftime("%Y%m%d")`，日期格式为 `20261013`（无连字符）。两者构造的 Redis Key 不同，DECR 操作无法匹配到正确的 Key |
| Key 模板 | `quota:analysis:{uid}:{date}` |
| membership 写入 | `quota:analysis:123:2026-10-13` |
| ai_pipeline 退还 | `quota:analysis:123:20261013` |
| 影响 | 分析失败后免费额度无法退还，用户每次失败都损失一次免费额度 |
| 修复建议 | 统一使用 `today.isoformat()`（ISO 8601 格式），ai_pipeline L929 改为 `today = date.today().isoformat()` |

**证据**：

```python
# 10-membership/backend.md L371（Key 模板定义）
QUOTA_KEY = "quota:analysis:{uid}:{date}"

# 10-membership/backend.md L472, L542, L628（写入时使用 ISO 格式）
today = date.today()
key = MembershipService.QUOTA_KEY.format(uid=user_id, date=today.isoformat())  # → quota:analysis:123:2026-10-13

# 13-infrastructure/ai_pipeline.md L929-930（退还时使用紧凑格式）
today = date.today().strftime("%Y%m%d")  # → "20261013"
key = f"quota:analysis:{user_id}:{today}"  # → quota:analysis:123:20261013
```

#### P1-REDIS-02：Redis Key 占位符命名不统一

| 项目 | 内容 |

| 问题描述 | membership 和 gamification 使用 `{uid}` 作为占位符，ai_pipeline 和 notification 使用 `{user_id}`，payment 使用内联 `{order.user_id}` |
| 影响范围 | |

| 模块 | Key 模板 | 占位符 |
|------|----------|--------|
| membership | `quota:analysis:{uid}:{date}` | `{uid}` |

#### P3-REDIS-03：Key 构造方式不统一

## 4. 维度③：跨模块调用签名匹配

### 4.1 检查方法

### 4.2 发现

#### P0-CALL-01：payment 调用未定义的 `MembershipService.revoke_subscription`

| 项目 | 内容 |
|------|------|
| 严重度 | **P0（严重 — 运行时 AttributeError）** |
| 涉及文件 | `11-payment/backend.md` L1271 → `10-membership/backend.md`（目标不存在） |
| 问题描述 | payment 退款逻辑中调用 `await MembershipService.revoke_subscription(db, order.subscription_id)`，但 membership 切片中 MembershipService 类未定义 `revoke_subscription` 方法。已定义的相关方法仅有 `apply_downgrade_policy(db, subscription)` 和 `_handle_downgrade(db, subscription)` |
| 调用代码 | `await MembershipService.revoke_subscription(db, order.subscription_id)` |
| 实际定义 | 无此方法。membership 仅有 `apply_downgrade_policy(db, subscription: Subscription)` 和 `_handle_expiry(db, subscription)` 和 `_handle_downgrade(db, subscription)` |
| 参数也不匹配 | payment 传入 `(db, order.subscription_id)`（int 类型），但 membership 的降级方法需要 `(db, subscription: Subscription)`（ORM 对象） |
| 影响 | 退款后无法撤销会员权益，用户退款后仍保持会员状态 |
| 修复建议 | 在 MembershipService 中新增 `revoke_subscription(db, subscription_id: int)` 方法：根据 subscription_id 查询 Subscription 对象，设置 status="closed"，调用 `apply_downgrade_policy` |

# 10-membership/backend.md L368-725（被调用方类定义）
class MembershipService:
    # ... 无 revoke_subscription 方法 ...
