### 2.2 积分触发链完整性审查（跨模块级联）

模块详细设计 BR-1 定义了 6 种积分事件：

| 事件 | 积分 | 触发模块 | 切片实际调用 | 状态 |
|------|------|---------|-------------|------|
| 完成 AI 分析 | +10 | ai_pipeline → gamification | ❌ ai_pipeline 无 add_points 调用 | **P0 缺失** |
| 完成记分牌比赛 | +5 | scoring → gamification | ❌ scoring 仅调 match_data（+3 record），未调 gamification match 事件 | **P0 缺失** |
| 手动录入比赛 | +3 | match_data → gamification | ✅ `add_points(db, user_id=user_id, event_type="record", ref_id=record_id)` | — |
| 每日打卡 | +2 | gamification checkin | ✅ checkin 端点内部 _add_points | — |
| 连续打卡 7 天 | +20 | gamification checkin | ✅ streak==7 触发额外奖励 | — |
| 连续打卡 30 天 | +100 | gamification checkin | ✅ streak==30 触发额外奖励 | — |
| 训练单完成 | 未定义 | training_advice → gamification | ❌ `add_points(db, user_id, 5, "training_session")` 参数错位 | **P0 签名错误** |

**结论**：6 个预定义积分事件中，3 个正常触发，3 个存在 P0 级问题。

## 三、未覆盖盲区发现

### 盲区-1：内容审核逻辑完全缺失（P1）

- **约束 #22** 要求：文本 DFA 敏感词过滤 + 图片/视频阿里云内容安全 API
- **现状**：14 份切片中无任何内容审核实现。用户反馈（video_analysis BR-3）中 is_correct=false 进入"人工审核队列"，但审核队列无切片定义
- **影响**：用户生成内容（反馈文本、分享内容）无敏感词过滤，存在合规风险
- **建议**：新建 `13-infrastructure/content_moderation.md` 切片，定义 DFA 过滤器 + 阿里云 API 集成

### 盲区-2：AI 分析完成积分触发缺失（P0）

- **预期**：ai_pipeline Step 10（结果聚合）完成后调用 `GamificationService.add_points(db, user_id, event_type="analysis")` → +10 积分
- **现状**：ai_pipeline.md 无任何 gamification 调用
- **影响**：用户完成 AI 分析后无法获得训练积分，连续打卡也无法自动触发（add_points 内部 _auto_checkin 不被调用）
- **建议**：在 ai_pipeline Step 10 后追加 `await GamificationService.add_points(db, user_id, event_type="analysis", ref_id=report_id)`

### 盲区-3：scoring 比赛完成积分触发缺失（P0）

- **预期**：scoring finish_match 后调用 `GamificationService.add_points(db, user_id, event_type="match")` → +5 积分
- **现状**：scoring/backend.md finish_match 仅调用 `MatchDataService.create_record_from_scoring`，后者使用 event_type="record"（+3），未触发 match 事件（+5）
- **影响**：记分牌比赛完成仅得 3 分（手动录入积分），比模块详细设计定义的 5 分少 2 分
- **建议**：scoring finish_match 中追加 `add_points(db, user_id, event_type="match")`，或将 match_data.create_record_from_scoring 内部改为根据来源区分 event_type

### 盲区-4：training_advice add_points 调用参数错位（P0）

- **定义签名**：`add_points(db: AsyncSession, user_id: int, event_type: str, ref_id: Optional[int] = None) -> int`
- **training_advice 实际调用**（line 1147）：
  ```python
  await GamificationService.add_points(db, user_id, 5, "training_session")
  ```
  - 第 3 参数 `5`（int）传给了 `event_type`（str）→ 类型错误
  - 第 4 参数 `"training_session"`（str）传给了 `ref_id`（Optional[int]）→ 类型错误
- **match_data 正确调用**（line 637-638）：
  ```python
  await GamificationService.add_points(db, user_id=user_id, event_type="record", ref_id=record_id)
  ```
- **额外问题**：`"training_session"` 不在 POINTS_RULES 中（只有 analysis/match/record/checkin/streak_7/streak_30），即使参数正确也返回 0 分
- **建议**：修改为 `add_points(db, user_id=user_id, event_type="record", ref_id=session_id)`，或在 POINTS_RULES 中新增 `"training_session": 5`

### 盲区-5：Model 路径命名不一致（P1）

- **架构 §10 目录树**（line 1848）：`app/models/progress.py`（文件名 `progress.py`）
- **training_advice 切片实际引用**（line 551）：`from app.models.progress_analysis import ProgressSnapshot, TechniqueTrend`（文件名 `progress_analysis.py`）
- **影响**：Python import 路径与架构约束不一致，运行时 ModuleNotFoundError
- **跟踪表状态**：A-10（AnalysisReport 路径）和 A-11（progress_analysis 路径）均 ⏳待修复
- **建议**：统一为 `app/models/progress_analysis.py`，架构 §10 目录树同步更新

### 盲区-6：conftest.py MockRedis hash 操作不完整（P2）

- **现状**：conftest.py.md 的 MockRedis 中 `hgetall` 返回空 dict、`hset` 返回 1 但不实际存储 hash
- **影响**：scoring 切片测试依赖 `redis.hgetall("match:{id}:current_score")` 读取比分缓存，Mock 下永远返回空 → 比分同步测试无法验证逻辑
- **建议**：补全 MockRedis 的 hset/hgetall 实现（用 dict 存储 hash 字段）

### 盲区-7：payment 测试存在 naive datetime（P2）

- **现状**：payment/backend.md line 76 使用 `datetime.now().strftime('%Y%m%d')`（naive datetime）
- **约束 #18（总览反幻觉约束）**：禁止 `datetime.utcnow()` naive datetime
- **跟踪表矛盾**：TD-12 标记 ✅（02-user+03-video_analysis 全局替换），A-9 仍 ⏳待修复
- **建议**：替换为 `datetime.now(timezone.utc).strftime('%Y%m%d')`，A-9 应确认覆盖全部切片

### 盲区-8：小程序分包体积约束未标注（P3）

- **约束 #25**：主包 ≤2MB，4 分包各 ≤2MB，总计 ≤8MB
- **现状**：总览 §3.4 app.config.ts 有分包配置，但未标注各包体积约束
- **建议**：在总览 §3.4 补充分包体积预算表
