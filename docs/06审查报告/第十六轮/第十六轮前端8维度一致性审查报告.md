## 3. 深层检查结果（8 项）

### 3.1 检查项 #8：useWebSocket 单例模式是否正确（多调用方共享连接，引用计数）

**位置**：12-notification/frontend.md L223-227, L298-382

**实现分析**：

模块级单例变量（L223-227）：
```typescript
let sharedSocket: Taro.SocketTask | null = null
let connectionCount = 0
const sharedListeners = new Set<Function>()
let sharedIsConnected = false
```

连接创建（L298-347）：`connect()` 检查 `if (sharedSocket)` 跳过重复创建 ✅

引用计数（L349-361）：`disconnect()` 递减 `connectionCount`，仅 `=0` 时关闭 ✅

`useEffect`（L372-382）：`connectionCount++` 挂载时、`disconnect()` 卸载时 ✅

**发现 P1 级缺陷**：`isManualCloseRef`（L242）为 `useRef`（实例级），非模块级变量。当创建连接的实例先于最后一个断开实例卸载时，`onClose` 回调捕获的是创建实例的 `isManualCloseRef`（值为 `false`），导致手动关闭后仍触发重连。

**故障场景**：
1. 实例 A 挂载 → `connect()` 创建 socket，`onClose` 闭包捕获 `isManualCloseRef_A`
2. 实例 B 挂载 → `connect()` 发现已连接，返回
3. 实例 A 卸载 → `connectionCount` 2→1，`disconnect()` 返回（不关闭）
4. 实例 B 卸载 → `connectionCount` 1→0，`isManualCloseRef_B=true`，调用 `close()`
5. `onClose` 触发 → 检查 `isManualCloseRef_A.current`（`false`）→ **错误触发重连** ❌

**结论**：⚠️ 单例模式基本正确但 `isManualCloseRef` 存在实例级闭包捕获缺陷（见 §4 P1-1）。

### 3.8 检查项 #15：useWebSocket 单例的 disconnect 逻辑（引用计数=0 才关闭）

**位置**：12-notification/frontend.md L349-361

```typescript
const disconnect = useCallback(() => {
    connectionCount = Math.max(0, connectionCount - 1)
    if (connectionCount > 0) return          // 引用计数 >0，不关闭
    isManualCloseRef.current = true           // 标记手动关闭
    if (heartbeatTimerRef.current) {
        clearInterval(heartbeatTimerRef.current)
    }
    socketRef.current?.close({})
    socketRef.current = null
    sharedSocket = null
}, [])
```

**引用计数逻辑**：✅ 正确——`Math.max(0, ...)` 防止负数，`if (connectionCount > 0) return` 仅在最后一个调用方断开时关闭。

**但发现关联缺陷**（与检查项 #8 一致）：

`disconnect()` 设置 `isManualCloseRef.current = true`，但此 ref 是当前 Hook 实例的 ref。`onClose` 回调捕获的是创建连接实例的 `isManualCloseRef`（见 §3.1 故障场景）。当断开实例 ≠ 创建实例时，`onClose` 看不到 `isManualCloseRef = true`，触发错误重连。

**修复建议**：将 `isManualCloseRef` 改为模块级变量 `let sharedIsManualClose = false`，与 `sharedSocket`/`connectionCount` 一致。

**结论**：⚠️ 引用计数逻辑本身正确，但 `isManualCloseRef` 实例级闭包捕获导致手动关闭后仍可能重连（见 §4 P1-1）。
