## 新发现问题

### P0 — `useWebSocket` Hook API 契约不匹配（跨 3 个模块）

**严重程度**：P0（运行时崩溃）

**涉及文件**：
- `12-notification/frontend.md` §4（L200-335）— `useWebSocket` 实现
- `04-scoring/frontend.md` §8（L1339-1383）— `useMatchSync` 消费方
- `09-gamification/frontend.md` §8（L1024-1077）— `useBadgeUnlock` 消费方

**问题描述**：

`useWebSocket` Hook 的实现与消费方期望的 API 接口不匹配，导致运行时崩溃。

| 视角 | 返回值签名 | 来源 |
|------|-----------|------|
| **实现（12-notification L333）** | `return { connect, disconnect }` | 实际代码 |
| **消费方 1（04-scoring L1351）** | 期望 `{ sendMessage, isConnected, onMessage }` | useMatchSync |
| **消费方 2（09-gamification L1039）** | 期望 `{ onMessage }` | useBadgeUnlock |

**运行时后果**：
1. `useMatchSync`：`isConnected` 始终为 `undefined`（falsy），导致 `if (!matchId || !isConnected) return` 永远提前退出，`sendMessage` 调用永远不执行 → 比赛房间 join 消息不会发送
2. `useBadgeUnlock`：`onMessage` 为 `undefined`，调用 `onMessage(handler)` → `TypeError: onMessage is not a function`
3. `useMatchSync`：即使绕过 isConnected 检查，`sendMessage(...)` → `TypeError: sendMessage is not a function`

**修复建议**：

在 `useWebSocket` 实现中补充暴露以下 API：

```typescript
// 12-notification/frontend.md useWebSocket.ts 补充
const [isConnected, setIsConnected] = useState(false)
const messageListenersRef = useRef<Set<(event: MessageEvent) => void>>(new Set())

// 在 task.onOpen 中：setIsConnected(true)
// 在 task.onClose 中：setIsConnected(false)

const sendMessage = useCallback((data: string) => {
  socketRef.current?.send({ data })
}, [])

const onMessage = useCallback((handler: (event: MessageEvent) => void) => {
  messageListenersRef.current.add(handler)
  return () => { messageListenersRef.current.delete(handler) }
}, [])

// 在 task.onMessage 中分发到所有注册的 listener
// task.onMessage((res) => {
//   handleMessage(res.data)
//   messageListenersRef.current.forEach(fn => fn(res))
// })

return { connect, disconnect, sendMessage, isConnected, onMessage }
```

### P2 — WebSocket 断线重连无用户可见提示

**严重程度**：P2（用户体验缺陷）

**涉及文件**：
- `12-notification/frontend.md` §4 useWebSocket（L292-303）— 重连逻辑
- `04-scoring/frontend.md` §8 useMatchSync — 记分牌场景
- `09-gamification/frontend.md` §8 useBadgeUnlock — 徽章解锁场景

**问题描述**：

`useWebSocket` 实现了指数退避重连（1s→2s→4s→8s→16s，最大 5 次），但断线期间和重连失败后均无用户可见的 UI 提示（无 Toast、无 Banner、无状态指示器）。

对比：`03-video_analysis/frontend.md` L602 有 `<Text className="ws-status">● {t('analysis.realtime')}</Text>` 显示连接状态，但其他模块无类似处理。

**影响场景**：
- 实时记分页（scoreboard）：设备 B 断线后不显示"连接断开"提示，用户无法感知多设备同步已失效
- 徽章解锁：断线期间解锁的徽章推送丢失，用户无感知

**修复建议**：
1. 在 `useWebSocket` 中暴露 `isConnected` 状态（与 P0 修复一致）
2. 在 scoreboard 页面顶部添加连接状态指示器：`{!isConnected && <View className="ws-disconnected-banner">{t('scoring.wsDisconnected')}</View>}`
3. 重连失败（5 次后）显示 Toast 提示用户手动刷新

### P2 — 全局无 ARIA 无障碍属性

**严重程度**：P2（无障碍合规缺陷）

**涉及文件**：全部 6 个前端切片文件（02-user、04-scoring、00-home、09-gamification、14-tab-pages/onboarding、06-data_dashboard）

**问题描述**：

对全部前端切片文件执行 `aria-label|aria-|role=` 模式搜索，**零匹配**。所有交互元素（按钮、输入框、可点击 View）均未设置任何 ARIA 属性。

**典型缺失场景**：
- scoring/scoreboard：大按钮 `<Button>` 记分按钮无 `aria-label`，屏幕阅读器无法朗读"我得分"/"对手得分"
- scoring/scoreboard：`<View onClick={handleUndo}>` 撤销按钮用文本"撤销"标注，但图标按钮（如通知铃铛🔔）无 `aria-label`
- user/edit：`<Input>` 表单无 `aria-label`，仅有 placeholder
- home/TopBar：`<View onClick={handleAvatar}>` 头像点击区无 `role="button"` 无 `aria-label`
- gamification/CheckinCalendar：日历格子无 `role="gridcell"` 无 `aria-selected`
- dashboard 折线图/环形图 SVG：无 `aria-label` 描述图表内容

**修复建议**：
1. 所有 `<Button>` 补充 `aria-label={t('xxx')}`（尤其图标按钮）
2. 所有 `<View onClick>` 补充 `role="button"` + `aria-label`
3. 所有 `<Input>` 补充 `aria-label={t('xxx')}`（与 placeholder 一致）
4. SVG 图表补充 `<svg role="img" aria-label={t('dashboard.winRateTrend')}>`

### P2 — 跨端 SVG 兼容性未处理

**严重程度**：P2（小程序端渲染风险）

**涉及文件**：
- `06-data_dashboard/frontend.md` §4.3 WinRateTrend（L573-586）— SVG 折线图
- `06-data_dashboard/frontend.md` §4.4 TechniqueStats（L655-674）— SVG 环形图

**问题描述**：

对全部前端切片执行 `#ifdef|#ifndef|process.env.TARO_ENV|TARO_ENV` 搜索，**零匹配**。项目无任何条件编译处理。

数据看板使用原生 `<svg>`/`<path>`/`<circle>`/`<text>` 元素绘制折线图和环形图。在小程序端（微信/支付宝），Taro 对原生 SVG 标签的支持有限或不一致：
- 微信小程序不支持 `<svg>` 标签，需要使用 `<canvas>` 或 Taro 的 SVG 封装组件
- H5 端 SVG 正常工作

**修复建议**：
```typescript
// 方案 A：条件编译
import { isH5 } from '@/utils/platform'
// H5 使用 SVG，小程序使用 Canvas
{isH5 ? <SvgChart /> : <CanvasChart />}

// 方案 B：统一使用 echarts-taro3（已在文档中提及但未采用）
```

### P3 — 无图片 lazy-load 实现

**严重程度**：P3（性能优化）

**涉及文件**：全部前端切片

**问题描述**：

对全部前端切片执行 `lazy-load|lazyLoad|lazy_load|IntersectionObserver` 搜索，**零匹配**。所有 `<Image>` 组件均未配置 lazy-load。

当前图片主要是头像（64px）、报告缩略图（64px）等小图，影响有限。但如果后续有图片列表场景（如社区动态流），缺少 lazy-load 将导致性能问题。

**修复建议**：在图片列表场景中引入 `lazy-load` 属性或 `IntersectionObserver` 按需加载。
