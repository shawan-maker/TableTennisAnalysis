## 新发现问题（4 项）

### P1-1：架构 §5.7 完全缺失 match_data 模块端点段

| 属性 | 内容 |
|------|------|
| 严重度 | P1 |
| 文件 | `docs/03系统架构/01-系统架构设计.md` §5.7（L803-942） |
| 描述 | §5.7 Phase 1 核心 API 端点清单列出 11 个模块的端点（auth/users/video-analysis/scoring/dashboard/training/gamification/membership+payment/notification/progress/training-enhanced），但 **match_data 模块整段缺失**。架构 §4.1 模块矩阵（L604）明确定义 match_data 为独立 Phase 1 模块，实施计划 S3（L92）交付 match_data，API 设计 §7（L1933-2079）定义 4 个端点（POST/GET/GET{id}/PATCH /match-data/records），但 §5.7 完全没有 match_data 小节 |
| 影响 | 架构 API 清单列 65 端点，实际 Phase 1 业务模块 79 端点，差值 14 中 match_data 占 4 个；跨文档计数表面不一致；API 设计 D-2 条目（L5931）明确标注"架构文档应在后续同步更新"但 13 轮审查均未同步 |
| 修复建议 | 在 §5.7 notification 小节之前或 scoring 之后新增 `#### 比赛数据模块 (/match-data)` 小节，列出 4 个端点：POST /match-data/records（创建比赛记录）、GET /match-data/records（记录列表）、GET /match-data/records/{record_id}（记录详情）、PATCH /match-data/records/{record_id}（编辑记录） |
| 备注 | API 设计 D-2 描述写"3 个端点"但实际 §7 定义 4 个（PATCH 是后续新增），修复时应以 API 设计 §7 实际 4 个为准 |
