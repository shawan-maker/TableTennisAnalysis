## 新发现问题

### P3-1：架构 §11.2 API 安全表缺少 CSRF 防护说明

| 项目 | 内容 |
|------|------|
| **优先级** | **P3** |
| **问题描述** | 架构文档 §11.2（L1973-1983）API 安全表覆盖了 CORS、请求限流、文件上传、SQL 注入、XSS、内容审核、签名验证 7 项安全机制，但未包含 CSRF（跨站请求伪造）防护说明。全文档 grep `CSRF`/`csrf` 在 `docs/` 目录下 0 匹配。 |
| **实际风险评估** | **无实际安全风险**。本架构使用 JWT Bearer Token（Authorization 头），不使用 Cookie 进行身份认证。CSRF 攻击的核心前提是浏览器自动携带 Cookie，而 Bearer Token 需要前端代码主动添加到请求头中，浏览器不会自动携带。因此 CSRF 攻击面不存在。 |
| **影响范围** | 纯文档完整性问题，不影响系统安全性。 |
| **修复建议** | 在架构 §11.2 API 安全表中添加一行：`| CSRF | 不适用（JWT Bearer Token） | 使用 Authorization 请求头传递 Token，非 Cookie 方式，浏览器不自动携带，CSRF 攻击面不存在 |` |
| **阻塞开发** | 否 |
