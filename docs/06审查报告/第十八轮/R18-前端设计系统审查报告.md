### P1（Important）— 3 项

#### P1-1：总览 L92 React Query 残留（R17-5 未完全修复）

- **文件**：`00-垂直切片设计总览.md` L92
- **问题**：L92 原文为"前端使用 React Query 管理并发请求与缓存（staleTime=30s）"，与 §3.2 L114"状态管理：Zustand"矛盾
- **背景**：R17 P2-10 修复了 API §14a 的 React Query → Zustand 引用，但遗漏了总览 L92
- **影响**：前端开发者读到 L92 会误以为项目使用 React Query，导致技术栈混乱
- **修复建议**：将 L92 改为"前端使用 Zustand 管理状态，并发请求通过 Promise.all 聚合（staleTime=30s 适用于 Zustand store 的缓存策略）"

#### P1-2：video_analysis WebSocket 使用 data.type 而非 data.event + 自建连接

- **文件**：`03-video_analysis/frontend.md` L559/L564/L567/L1975/L1978
- **问题**：
  1. L559: `socketTask.send({ data: JSON.stringify({ type: 'subscribe', channel: ... }) })` — 订阅消息使用 `type` 字段
  2. L564: `if (data.type === 'analysis_progress' ...)` — 消息分发使用 `data.type`
  3. L567: `if (data.type === 'analysis_complete' ...)` — 同上
  4. L1975/L1978: 重复出现的 useAnalysisProgress hook 中相同的 `data.type` 模式
- **矛盾**：
  - §3.3 L164 定义事件类型列表（analysis_progress/analysis_complete 等），R15 P0-4~5 已将 useMatchSync 从 `msg.type` 修正为 `msg.event`
  - 统一 useWebSocket hook（notification/frontend.md L249）使用 `switch (msg.event)` 分发
  - scoring/frontend.md L1382-1390 使用 `msg.event` — 已修复
  - gamification/frontend.md L1051 使用 `data.event` — 已修复
  - **但 video_analysis 仍使用 `data.type`** — R15 遗漏
- **附加问题**：video_analysis `useAnalysisProgress`（L947/L1947）创建自己的 `Taro.connectSocket` 连接，未使用统一 `useWebSocket` hook，违反"ALL WebSocket 连接通过自定义 Hook useWebSocket 管理"约束
- **修复建议**：
  1. L559: `{ type: 'subscribe' }` → `{ event: 'subscribe' }`
  2. L564/L567/L1975/L1978: `data.type` → `data.event`
  3. 重构 useAnalysisProgress 使用统一 `useWebSocket` hook（或保留独立连接但统一消息字段）

#### P1-3：match-tab.md 端点路径不一致

- **文件**：`14-tab-pages/match-tab.md` L56
- **问题**：L56 `return request.get('/match-data', { page: 1, page_size: 1 })` 调用 `/match-data` 端点
- **正确路径**：`05-match_data/frontend.md` L80-81 `return request.get('/match-data/records', { result, page, page_size })` — 正确端点为 `/match-data/records`
- **影响**：运行时调用 `/match-data` 会返回 404 或路由匹配错误
- **修复建议**：L56 改为 `return request.get('/match-data/records', { page: 1, page_size: 1 })`

### P2（Moderate）— 4 项

#### P2-1：border-radius 硬编码值与 CSS 变量混用

- **文件**：8 个文件共 50+ 处
- **问题**：设计系统定义 `--radius-sm(8px)` / `--radius-md(12px)` / `--radius-lg(16px)`，但部分文件使用 CSS 变量，部分使用硬编码值

| 使用模式 | 文件 | 处数 |
|----------|------|------|
| ✅ var(--radius-md/sm) | community-tab, training-tab, match-tab, onboarding, data_dashboard, training_advice(部分) | ~40 |
| ❌ 硬编码 12px | match_data(11), video_analysis(6), scoring(2), membership(6), payment(4), gamification(3), notification(1) | 33 |
| ❌ 硬编码 8px | match_data(4), video_analysis(8), auth(2), notification(1), membership(2), scoring(1) | 18 |
| ✅ 50% | community-tab(1), match-tab(1) | 2 |

- **根因**：R9 P3-SPACE 脚本明确"非间距属性（border-radius）不替换"，后续部分文件手动修复但未全覆盖
- **修复建议**：批量替换 `border-radius: 12px` → `border-radius: var(--radius-md)`，`border-radius: 8px` → `border-radius: var(--radius-sm)`。`border-radius: 50%`（圆形元素）保持不变
