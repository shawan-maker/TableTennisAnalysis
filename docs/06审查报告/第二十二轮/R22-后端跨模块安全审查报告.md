- **告警映射**：6 条告警规则（P95 > 0.5s / P99 > 2s / 单任务 > 10min / 队列 > 10 / 失败率 > 5% / WS > 5000）

### 15.3 Sentry 错误追踪

- **初始化**：`configure_sentry(sentry_dsn, environment, traces_sample_rate)` 在 `SENTRY_DSN` 为空时跳过（dev 环境不初始化）
- **集成**：FastApiIntegration / CeleryIntegration / RedisIntegration / SqlalchemyIntegration / LoggingIntegration
- **脱敏**：`before_send` 钩子脱敏 `request.data` 和 `extra` 中的 9 个敏感字段
- **采样**：生产 100% ERROR 采样；WARNING 10% 采样；`traces_sample_rate=0.1` 性能事务采样
- **过滤**：`ignore_errors=[HTTPException, AppException]`（R19-P2-7 已改为异常类对象列表，`sentry.md` L94-97）排除 4xx 业务错误
- **手动上报**：AI 分析失败 / 微信支付验签失败 / GPU OOM 恢复失败 / Celery 重试耗尽 4 个关键场景

### 15.4 OpenTelemetry 分布式追踪（架构规划）

- 架构 §13.1 已补充 OpenTelemetry + Jaeger 10% 采样方案（`00-垂直切片设计总览.md` L671 引用）
- `request_id` 与 Sentry `set_tag("request_id", ...)` 一致，可通过 `request_id` 在日志和 Sentry 之间交叉查询
- 5xx 上报策略：AppException status_code >= 500 → Sentry `capture_exception`；4xx 仅 structlog WARNING，不上报
- 未捕获异常：`unhandled_exception_handler` 记录 ERROR 日志 + 上报 Sentry + 返回 500 通用错误

### 15.5 三件套协同设计

- **request_id 关联**：structlog 的 `request_id` 与 Sentry 的 `set_tag("request_id", ...)` 一致
- **5xx 上报策略**：AppException status_code >= 500 → Sentry `capture_exception`；4xx 仅 structlog WARNING
