## 2. 跨模块调用一致性表

### 2.1 MembershipService 跨模块调用签名

| 调用方切片 | 调用代码 | 实际定义签名 | 一致性 | 严重度 |
|-----------|---------|-------------|--------|--------|
| 03-video_analysis | `MembershipService.check_membership_active(user_id)` | `check_membership(db: AsyncSession, user_id: int) -> MembershipCheckResult` | ❌ 方法名错误 + 缺 db 参数 | **P0** |
| 07-training_advice | `MembershipService.check_membership(user_id)` | `check_membership(db: AsyncSession, user_id: int) -> MembershipCheckResult` | ⚠️ 方法名正确但缺 db 参数 + 返回值类型不匹配（期望 bool，实际返回 MembershipCheckResult） | **P0** |
| 01-auth | `MembershipService.get_current_membership(user.id)` | `get_current_membership(db: AsyncSession, user_id: int) -> CurrentMembershipResponse` | ⚠️ 方法名正确但缺 db 参数 + 返回值用法错误（以 dict 方式 `.get("tier")` 访问 Pydantic 模型属性） | **P1** |
| 03-video_analysis | `MembershipService.consume_analysis_quota(user_id)` | `consume_analysis_quota(user_id: int) -> bool` | ✅ 一致 | — |
| 10-membership (内部) | `MembershipService._get_active_subscription(db, user_id)` | `_get_active_subscription(db: AsyncSession, user_id: int)` | ✅ 一致 | — |
| 11-payment | `PaymentService._create_or_renew_subscription(db, order)` | 内部方法，签名一致 | ✅ 一致 | — |

### 2.2 NotificationService 跨模块调用签名

| 调用方切片 | 调用代码 | 实际定义签名 | 一致性 | 严重度 |
|-----------|---------|-------------|--------|--------|
| 11-payment | `NotificationService.push_ws_message(user_id, event_type, data)` | `send_notification(user_id, notif_type, title, content, extra_data, wechat_template)` 或 `_push_ws(user_id, event, data)` | ❌ 方法名 `push_ws_message` 不存在 | **P0** |
| 10-membership | `redis.publish(f"ws:user:{user_id}", payload)` (直接 Redis pub) | `NotificationService._push_ws(user_id, event, data)` 使用相同 Redis channel | ⚠️ 绕过 NotificationService 直接操作 Redis，格式可能不一致 | **P2** |
| 09-gamification | `redis.publish(f"ws:user:{user_id}", payload)` (直接 Redis pub) | 同上 | ⚠️ 绕过 NotificationService | **P2** |

### 2.3 跨模块调用一致性结论

- **3 个 P0 阻塞问题**：
  1. video_analysis 调用了不存在的 `check_membership_active` 方法
  2. training_advice 调用 `check_membership` 缺少 `db` 参数且返回值类型假设错误
  3. payment 调用了不存在的 `NotificationService.push_ws_message` 方法
- **2 个 P1 问题**：auth 模块 `get_current_membership` 调用缺 db 参数 + 返回值访问方式错误
- **2 个 P2 问题**：membership 和 gamification 绕过 NotificationService 直接 Redis publish

**根因分析**：membership 切片将 `check_membership` 定义为需要 `db: AsyncSession` 参数的静态方法，但所有调用方（video_analysis/training_advice/auth）都假设它是不需要 db 的简化签名。这说明切片设计时未统一接口契约。

- **4 个 P1 断链**：看板 bust 未触发（D-3/D-8）+ 比赛结束积分/打卡未联动（D-6/D-7）
- **1 个 P2 断链**：会员降级标记写入但消费方未实现读取逻辑（D-12）

**根因分析**：模块设计 §6 定义了完整的级联事件实现方式表（Celery chain），但切片设计中未实现 Celery chain 编排代码。需要在 ai_pipeline 或独立级联任务模块中补充。

## 9. 优化建议

### 9.1 架构级优化

1. **统一跨模块调用契约**：为所有跨模块 Service 调用定义接口契约文档，明确方法名、参数类型、返回值类型。建议在模块详细设计中增加「对外暴露方法签名表」。

2. **补充级联事件编排模块**：创建 `app/tasks/cascade_chains.py` 统一管理 3 条级联链（AI 分析完成 / 支付成功 / 比赛结束），使用 Celery chain 编排，避免散落在各 Service 中。

3. **Redis Key 命名规范**：制定统一的 Redis Key 命名规范文档，格式为 `{module}:{purpose}:{id}[:{sub_id}][:{date}]`，并为所有 Key 定义常量类 + TTL 常量。

4. **补充基础设施切片**：为 knowledge_base / ai_pipeline / ai_inference / file_management / admin 创建独立切片文件，确保 S6 Sprint 可按切片模式开发。

### 9.2 模块级优化

5. **membership `consume_analysis_quota` 签名优化**：当前方法内部创建 `async_session_factory()` 获取 db，建议保持此设计（不要求调用方传 db），但需将 `check_membership` 也改为同样模式或在文档中明确区分「需 db 参数」与「不需 db 参数」两类方法。

6. **notification WS 推送统一入口**：所有模块的 WS 推送都应通过 `NotificationService._push_ws(user_id, event, data)` 调用，禁止直接 `redis.publish(f"ws:user:{user_id}", ...)`，确保消息格式统一。

7. **payment 异步上下文修复**：将 `_get_wechat_platform_cert` 改为 async 方法，或使用 `asyncio.to_thread` 包装同步 Redis 调用。

8. **notification Celery task 修复**：`training_reminder_task` 应定义为同步函数内部使用 `asyncio.run()`，或使用 celery 的 async 支持（如 `celery[asyncio]`）。

### 9.3 数据层优化

9. **RefundRecord 注册**：在 `app/models/__init__.py` 导入列表中补充 `RefundRecord`。

10. **MembershipTier 字段回写**：将 `is_active`/`created_at`/`updated_at` 字段回写至数据库详细设计 §2.31。

11. **payment 测试 fixture 修复**：修正 `payment_ctx` fixture 中的缩进错误。
