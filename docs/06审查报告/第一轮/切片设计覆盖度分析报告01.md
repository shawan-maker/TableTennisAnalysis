## 二、模块 01-06 分析摘要

> 以下为上一轮分析的核心发现摘要，详细表格已直接输出给用户。

### 01-auth

- API 端点、DB 模型、业务规则、前端页面均与基准一致，无显著缺失。
- 微信登录 JWT 签发 + Token 刷新 + 登出流程完整。

### 02-user

- **P1 缺失**：§3.7 反馈历史查询端点在 user 和 video_analysis 两个模块的切片中均未实现。
- **P2 缺失**：用户注销功能无前端 UI；用户数据导出功能无前端 UI。
- **字段不一致**：user_profile 表在切片中被合并到 User 模型（DB 设计中为独立表）。

### 03-video_analysis

- **P1 缺失**：PipelineStep 模型在 03 切片中未定义（已由 13b-ai_pipeline 切片补充）。
- **P1 字段不一致**：VideoTask 主键类型——切片用数字 `id`，DB 设计用字符串 `task_id`（UUID），Alembic 迁移将产生冲突。
- **字段不一致**：ShareRecord 字段名偏差、FeedbackRecord 多余 `status` 字段。

### 04-scoring

- **P1 缺失**：scoring setup→in_progress API 端点缺失，比赛创建后无法进入记分流程（状态机入口断链）。
- **P2 未实现**：abandoned 状态及 24h 恢复机制未实现。
- **字段不一致**：ManualScoreDetail FK 名称与 DB 设计不匹配。

### 05-match_data

- **P2 缺失**：F5 手动编辑比赛数据功能未实现。
- **字段不一致**：MatchStatistic.stats_data 类型——切片用 Text，DB 设计用 JSONB。

### 06-data_dashboard

- 与基准文档一致性最高，无显著缺失或偏差。
- API 端点、DB 模型、业务规则、前端页面全覆盖。

- BadgeProgress（badge_progress 表）

## 五、跨模块字段不一致模式

01-06 和 07-13 分析中发现的字段不一致问题可归纳为以下模式：

1. **表名/字段名简化**：切片倾向于使用更简洁的命名（membership_tier vs membership_tier_config，trend vs trend_direction，price_monthly vs price_monthly_cents）。建议统一以切片命名为准，回写 DB 设计文档。
2. **表结构重构**：user_points 从汇总表变为变动记录表，user_profile 被合并到 User 模型。这类变更需确认设计意图后统一。
3. **类型不一致**：VideoTask 主键（数字 vs UUID 字符串）、MatchStatistic.stats_data（Text vs JSONB）、AnalysisReport.result_data（str vs dict）。建议统一为 DB 设计类型或协商后统一。
4. **FK 名称偏差**：ManualScoreDetail FK 名称与 DB 设计不匹配，Subscription.user_id 目标表需与 user_profile 合并方案一致。
5. **新增表未回写**：badge 相关 3 张表、refund_record 表在切片中定义或引用但未出现在 DB 设计文档中。
