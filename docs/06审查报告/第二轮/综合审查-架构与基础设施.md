- `Dockerfile`（主应用 + GPU 服务各一个）
- `docker-compose.yml`（开发环境）
- `docker-compose.prod.yml`（生产环境）
- §9.2 声明"docker-compose.yml 统一编排以上所有服务"

**切片审查结果**：所有 17 个切片（12 后端 + 5 基础设施）**均未**包含 Dockerfile 或 docker-compose 配置。

| ID | 优先级 | 描述 | 涉及文档 |
|----|--------|------|---------|
| DEP-1 | P1 | 架构明确定义 Docker + Docker Compose 作为容器化方案，但没有任何切片提供 Dockerfile 模板或 docker-compose 编排文件。架构目录树列出了 `Dockerfile` 和 `docker-compose.yml` 文件名，但内容未设计。**建议在基础设施切片中补充 Dockerfile + docker-compose.yml 设计。** | 架构 §2.3, §8, §9.2; 全部切片 |

**结论**：GPU 服务部署方案在架构与切片间一致。

## 9. 错误处理一致性

### 9.1 统一异常体系

架构 §7 定义统一异常处理：

- `AppException(message, code)` 作为唯一业务异常类型
- 全局异常处理器返回统一 JSON 响应

**切片审查结果**：所有 17 个切片统一使用 `from app.core.exceptions import AppException`，**禁止**创建新的异常类型。✅ 完全一致。

### 9.2 HTTP 状态码使用

| 场景 | 架构约定 | 切片实际使用 | 一致性 |
|------|---------|-------------|--------|
| 资源不存在 | 404 | 所有切片：`AppException("xxx不存在", 404)` | ✅ |
| 参数校验失败 | 422 | Pydantic 自动返回 422 + Service 层 `AppException("xxx", 422)` | ✅ |
| 权限不足 | 401/403 | 401 无 Token、403 额度不足 | ✅ |
| 业务冲突 | 409 | 重复打卡 409、重复注销 409、比分已更新 409 | ✅ |
| 限流 | 429 | 分享超限 429、导出超限 429 | ✅ |

### 9.3 熔断器

架构 §7 定义 Circuit Breaker 模式：5 次失败 → 60s 半开。

| 切片 | 熔断器实现 | 一致性 |
|------|-----------|--------|
| ai_pipeline → ai_inference 调用 | 切片定义了健康检查 + 降级策略 | ✅ 一致 |
| video_analysis → file_service 调用 | HEAD Object 失败直接 raise | ⚠️ 无重试 |

### 9.4 发现项

| ID | 优先级 | 描述 | 涉及文档 |
