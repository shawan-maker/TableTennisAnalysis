## 5. Redis Key 命名一致性 ⚠️

### 5.1 quota:analysis Key 日期格式跨模块不一致（P1-1）

同一逻辑的 Redis Key `quota:analysis:{user_id}:{date}` 在三个模块中使用了不同的日期格式：

| 模块 | 文件+行号 | 日期格式 | Key 示例 |
|------|----------|----------|----------|
| video_analysis | `03-video_analysis/backend.md` L659 | `strftime("%Y%m%d")` | `quota:analysis:1:20261015` |
| membership | `10-membership/backend.md` L550/636 | `date.today().isoformat()` | `quota:analysis:1:2026-10-15` |
| ai_pipeline | `13-infrastructure/ai_pipeline.md` L869 | `date.today().isoformat()` | `quota:analysis:1:2026-10-15` |

**影响**：video_analysis 的 `_check_free_quota`（L654-670）与 membership 的 `consume_analysis_quota`（L528-564）各自独立维护额度计数，且 Key 格式不同导致同一用户同一天的计数在不同 Key 上累计。当 video_analysis 先用 `20261015` 格式 INCR 后，membership 再用 `2026-10-15` 格式查询时读到 0，免费额度限制形同虚设。

**根因**：video_analysis 使用 Asia/Shanghai 时区的 `strftime("%Y%m%d")`，membership 和 ai_pipeline 使用 `date.today().isoformat()`（本地系统时区的 ISO 日期），两者不仅格式不同，时区基准也可能不同。

**修复方向**：统一为一种格式。建议使用 `date.today().isoformat()`（`2026-10-15` 格式），与 membership 和 ai_pipeline 保持一致；同时统一时区基准为 Asia/Shanghai。

### 5.2 share:count Key 日期格式

`03-video_analysis/backend.md` L978-979 的 `share:count:{user_id}:{date_key}` 使用 `strftime("%Y%m%d")`，与 quota:analysis 同模块但不同逻辑，暂无跨模块不一致问题。
