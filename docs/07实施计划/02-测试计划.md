### 1.2 测试策略

采用**金字塔模型**，从底层到高层逐级覆盖：

```
        ┌───────────┐
        │   E2E 5条  │  ← Playwright（Taro H5 mode）
        ├───────────┤
        │  集成测试   │  ← pytest + testcontainers（PG + Redis）
        ├───────────┤
        │  接口测试   │  ← pytest + httpx AsyncClient + conftest fixtures
        ├───────────┤
        │  单元测试   │  ← pytest + Mock（Service 层 + 工具函数）≥80%
        └───────────┘
```

**分层策略**：
- **单元测试**：Service 层业务逻辑 + 工具函数 + Pydantic Schema 校验 + 枚举值域，隔离 DB/Redis（内存 SQLite + MockRedis），覆盖率 ≥80%
- **接口测试**：96 端点逐个验证正向 + 逆向（参数校验/权限/限流/状态码/错误码），使用 conftest 公共 fixture（client/auth_user/admin_user），覆盖率 100%
- **集成测试**：跨模块数据流（AI 级联/支付链/比赛链/注销链/数据飞轮）+ DB 外键约束 + Redis Key 过期 + Celery 任务执行，覆盖率 ≥70%（核心模块 100%）
- **E2E 测试**：5 条核心用户路径端到端验证（Playwright H5 mode），覆盖用户真实操作流程
- **质量属性专项**：性能压测（locust 100 并发）/ 安全扫描（SQLi+XSS+CSRF+JWT+加密）/ 可用性（熔断+WS 重连+灰度）/ 兼容性（小程序+H5 降级）

### 5.1 接口测试通用规范

#### 5.1.1 统一响应格式验证

每个端点响应必须验证：
```python
assert response.status_code == expected_status
assert response.json()["code"] == expected_code
assert response.json()["message"] is not None
assert "data" in response.json()
assert "timestamp" in response.json()
```

#### 5.1.2 分页响应验证

列表端点必须验证：
```python
assert "total" in data
assert "page" in data
assert "page_size" in data
assert "items" in data
assert isinstance(data["items"], list)
assert len(data["items"]) <= data["page_size"]
```
