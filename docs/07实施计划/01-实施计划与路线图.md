> **v1.2 重构说明（最快见效原则）**：
>
> 1. **S1 精简为 2 周**：仅保留微信登录 + 基础档案 + 免费额度 + 前端框架。手机号登录、趣味统计卡片、数据导出、consent 链路移至 S6 补充。
> 2. **S2 记分牌先行**：记分牌不依赖 AI，仅需 WebSocket + Redis + 状态机。W4 即可交付原型①（创建比赛→记分→多设备同步→统计），让用户最早用起来。
> 3. **S3 视频分析后移至 W5**：Phase 0 AI POC 在 W2 已完成，W5 开始视频分析时模型就绪。S3 完成后交付原型②（视频分析+数据看板），与 S2 记分数据联动。
> 4. **通知系统拆分**：基础 WS 通道（ws:match:{mid}）前移至 S2（记分牌需要），完整通知系统（模板+微信订阅消息+审计）保留在 S6。
> 5. **知识库前移至 S4**：原 S6 的 knowledge_base 前移至 S4，与 training_advice 同期开发（知识库是训练建议的前置依赖）。
> 6. **总工期从 18 周缩短至 16 周**，第一个可试用原型从 W6 提前至 W4。

| WS 延迟 | 记分牌同步延迟 | <200ms |
| 用户指标 | 注册用户 | ≥1000 |
| 使用指标 | 视频分析次数 | ≥500 |
| 质量指标 | 用户满意度 | >70% |
| 商业指标 | 付费转化率 | >5% |
| 留存指标 | 次日留存率 | >30% |

> **P2 API P95 性能约束（通用约定）**：所有列表 API 必须分页，禁止 N+1 查询，列表接口 P95 < 500ms。后端 Service 层必须使用 `selectinload` 或 `joinedload` 预加载关联数据，禁止在循环中逐条查询。分页参数统一为 `page` + `page_size`（默认 20，最大 50），响应格式遵循 `{total, page, page_size, items}`。
>
> **错误处理统一规范（R18+ 审查确认）**：全部 API 端点统一使用 `raise AppException(...)` 抛出业务错误，禁止直接使用 `HTTPException`。共 105 个错误码（含 admin 21 处），分布在通用错误码 + 业务错误码两个层次。`AppException` 中间件统一捕获并转换为标准 JSON 响应。
>
> **model_validate 注入规范（R18+ 审查确认）**：Service 层从 ORM Model 到 Pydantic Schema 的转换必须使用 `Schema.model_validate(orm_obj)` 注入，禁止手动逐字段赋值。共 22 处 `model_validate` 调用覆盖 10 个业务切片 + admin 切片。
>
> **consent 链路完整性（R22+ 审查确认）**：微信登录 + 手机号登录端点必须计算 `requires_consent` 并注入响应，consent 链路共 17 处对称实现（前端请求 ↔ 后端计算 ↔ 响应注入 ↔ 前端跳转）。

## 12. Anti-Hallucination 约束（实施计划专用）

1. **Phase 顺序不可跳级**：Phase N 的模块必须在 Phase N-1 全部上线后才可进入开发，不可并行跨 Phase 开发
2. **Sprint 内部可调整**：Sprint 内任务顺序和工时可灵活调整，但 Sprint 交付物不可删减
3. **3D内容生产可外包**：3D模型制作可外包或使用AI辅助，不阻塞其他 Phase 2 模块开发
4. **Phase 0 Go/No-Go 不可跳过**：AI模型精度未达标不可进入 Phase 1 正式开发
5. **每个 Phase 必须有验收**：Phase 验收标准中的指标必须达标才可标记 Phase 完成
6. **数据库 migration 不可跳过**：所有表变更必须通过 Alembic migration 管理，禁止手动DDL
7. **CI/CD 不可跳过**：所有代码必须通过 CI pipeline 才可部署，禁止手动部署到生产
8. **灰度发布必须逐步**：100→500→1000 逐步放量，不可直接全量发布
9. **成本监控必须启用**：从 Phase 1 开始必须有日成本告警，GPU 闲置必须关闭
10. **文档同步更新**：代码变更影响设计文档时，必须同步更新对应文档版本号

> **完整约束清单**：上述 10 条为实施计划专用约束。系统架构设计 `docs/03系统架构/01-系统架构设计.md` §15 定义了完整的 42 条 Anti-Hallucination 约束，覆盖架构层 / 数据层 / API 层 / 安全层 / 性能层，R1-R32 审查连续第十五轮 100% 合规。此外，16 个盲区排查清单和 8 个规则域跨文档一致性检查在审查报告中持续跟踪（连续第十二轮 16/16 + 8/8）。
